# P2PSocket_AI · P2P 内网穿透产品

> 基于开源项目 [P2PSocket](https://github.com/bobowire/Wireboy.Socket.P2PSocket) 的 AI 重构产品（原项目地址）

一个**可自部署**的 P2P 内网穿透产品：把一台设备（服务方）上的内网服务，经 **P2P 打洞直连隧道** 暴露给另一台设备（访问方）。访问方在本机连接 `虚拟IP:本地端口`，流量经端到端加密隧道直达对端——无需公网中转（打洞失败时可回退内置中继）。

## 1. 项目架构 & 如何联系

### 1.1 产品组成

| 组件 | 说明 |
|---|---|
| P2P.Server（服务端） | 部署在公网服务器：注册/授权/信令/STUN/中继兜底 + Web 管理后台 |
| P2P.Client（客户端） | 部署在用户设备：系统服务 + 本地 Web 管理页 |
| 虚拟网卡 | Windows Wintun / Linux TUN，本机统一监听地址 `100.64.0.2` |
| Web 控制台 | 客户端简易/高级双模式 + 服务端管理后台（Vue 3 + Element Plus，SPA 嵌入二进制） |

**设计原则**：控制面集中、数据面 P2P——服务端不做业务流量中转（打洞失败回退中继除外）；全链路不依赖 TLS——隧道 ECDH(P-256)+HKDF+AES-256-GCM 端到端加密，控制通道 HMAC-SHA256 防重放。

### 1.2 技术栈

| 层 | 选型 |
|---|---|
| 运行时 | **.NET 10**（C# · ASP.NET Core Minimal API · Generic Host · System.IO.Pipelines） |
| 前端 | Vue 3 + TypeScript + Element Plus + Vite（pnpm workspace） |
| 存储 | 服务端 SQLite + EF Core（WAL）；客户端本地 JSON |
| 协议 | MessagePack 编码；控制协议 PCP（7000/TCP）+ STUN（3478） |

| 测试 | xUnit + NatSimulator（NAT 模拟），全仓 700+ 项自动化测试 |

## 2. 项目使用场景

1. **远程桌面**：不同内网的 2 台电脑，使用 mstsc、teamviewer 等远程控制——公司电脑建立映射，家里访问 `100.64.0.2:3588` 直达远程桌面 3389 端口
2. **内网服务发布**：类似花生壳，将内网网站、数据库、SVN 等服务暴露给指定设备或分组访问
3. **跨网络设备互访**：SSH、文件共享、NAS、监控画面等内网 TCP 服务，跨家庭/办公/IDC 网络直连互通
4. **自托管、数据不经第三方**：服务端完全自部署，业务流量端到端加密直连，公网服务器只做握手与兜底

设备可见性：两台设备互相可见的前提是**登录同一账号**或**处于同一分组**；支持邀请码入组、分组所有者审批、按设备授权等闭环控制。

## 4. 项目网络架构

```
访问方设备 A                     服务端（公网部署）                  服务方设备 B
┌──────────────┐                ┌───────────────┐                ┌──────────────┐
│ P2P.Client   │◀──控制 7000/TCP▶│ P2P.Server    │◀──控制 7000/TCP─│ P2P.Client   │
│ 虚拟IP 100.64.0.2│  STUN 3478  │ SQLite·注册/授权│  STUN 3478     │ 虚拟IP 100.64.0.2│
│ 本地Web 127.0.0.1:7100│        │ Web 仅本机:7500 │               │ 本地Web 127.0.0.1:7100│
└──────┬───────┘                └───────────────┘                └──────┬───────┘
       │        UDP 打洞 → PTP 加密隧道（channel 复用；失败→中继 7010）       │
       └──────────────────────────────────────────────────────────────────┘
本地应用连 100.64.0.2:8080 ──▶ 映射引擎 ──▶ 隧道 channel ──▶ 对端 127.0.0.1:22
```

- 打洞成功 → 设备间直连（direct），业务流量不经过服务端
- 打洞失败（NAT 组合不可穿透）→ 目标设备开启中继回退时，经服务端中继转发（relay），服务仍可用
- 同一设备对只建一条隧道，全部映射以 channel 复用，不按连接重复打洞
- 直连优先：两台设备在同一局域网、或一方有公网 IP 可直达时，无需穿透 NAT 即刻建连

端口与地址规划：

| 用途 | 值 | 说明 |
|---|---|---|
| 控制协议 PCP | 7000/TCP | 注册/鉴权/心跳/信令 |
| STUN | 3478/UDP+TCP | 公网端点探测（带设备认证） |
| 中继 | 7010-7020/UDP+TCP | 打洞失败回退路径（端口段须安全组放行） |
| 客户端本地 Web | 127.0.0.1:7100 | 仅本机回环可达 |
| 服务端 Web | 127.0.0.1:7500 | 默认仅本机，经 SSH 隧道或映射接入 |
| 虚拟网段 | 100.64.0.0/24（固定 .2） | 仅作本机监听地址，各设备同值 |

## 5. 用户使用手册

**第一步：安装部署**（随版交付，见 [docs/deploy/](docs/deploy/)）

1. [服务端部署手册](docs/deploy/服务端部署手册.md)——公网服务器安装 P2P.Server、放行端口、初始化管理员
2. [Windows 客户端部署手册](docs/deploy/Windows客户端部署手册.md)——安装包部署，注册为系统服务
3. [Linux 客户端部署手册](docs/deploy/Linux客户端部署手册.md)——systemd 部署

**第二步：日常使用**（详见 [用户使用手册](docs/manual/用户使用手册.md)）

1. 客户端登录账号，首启向导完成初始化
2. 打开客户端管理页 `http://127.0.0.1:7100`（默认简易版），在「端口映射」新建映射：填目标设备的 6 位**远程码** + 目标端口（如远程桌面填 3389）
3. 本机访问 `100.64.0.2:本地端口` 即达对端服务；打洞直连优先，失败按策略自动回退中继
4. 服务端管理员访问 `http://<服务端>:7500` 管理用户/设备/分组/中继/安全中心

**故障排查**：[排障指南](docs/manual/troubleshooting.md)（按症状速查表定位条目）

**从源码构建**（依赖：.NET 10 SDK、Node ≥ 20、pnpm）：

```bash
sh build/build.sh            # 一条命令全链：dotnet build → API 类型导出 → 前端构建 → dotnet test
sh build/package.sh all      # 打包交付物：Windows Setup / Linux tar / 服务端 tar
```
