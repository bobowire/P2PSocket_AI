## 4. 配置要点(appsettings.json,相对工作目录 `/opt/p2p/server/`)

|---|---|---|

| `listen.webBind` | **0.0.0.0**(已改,默认 127.0.0.1) | 为 M2 Web 后台公网可达预置;M1 无监听无安全影响,如顾虑可改回 |

| `logging.retentionDays` | 14 | 日志保留 |

## 5. systemd 服务(`p2p-server.service`)

- Unit 文件:`/etc/systemd/system/p2p-server.service`(`WorkingDirectory=/opt/p2p/server`,`Restart=always`/5s 崩溃自愈,`enable` 开机自启)
- 常用运维命令(服务器上执行):

```bash
systemctl status p2p-server      # 状态
systemctl restart p2p-server     # 重启
journalctl -u p2p-server -f      # 跟随日志(systemd 侧)
tail -f /opt/p2p/server/logs/app-$(date +%Y%m%d).log   # 应用日志
```

- admin 密码重置(07 §9 R6,默认 admin/admin,重置后须尽快改密):

```bash
cd /opt/p2p/server && ./p2p-server --reset-admin
```

## 6. 首次部署实录(2026-09-11 实际操作,新服务器可按此复用)

> `<IP>` 代指目标服务器公网 IP(本次为 139.155.70.54);全部命令在本机仓库根目录执行,服务器操作均经 SSH 免密完成。

### 步骤 0 · SSH 免密前置

```bash
# 本机无密钥时先生成(有 ~/.ssh/id_ed25519 可跳过)
ssh-keygen -t ed25519
# 把公钥装到服务器(逐条回车输一次密码;或经云控制台/VNC 手工把
# ~/.ssh/id_ed25519.pub 内容追加到服务器 /root/.ssh/authorized_keys —— 本次实录即此路径)
ssh-copy-id root@<IP>
# 验证免密:
ssh -o BatchMode=yes root@<IP> "hostname"
```

### 步骤 1 · 本机发布(linux-x64 自包含单文件)

```bash
dotnet publish src/P2P.Server -c Release -r linux-x64 -p:PublishSingleFile=true -p:SelfContained=true -o out/server
```

### 步骤 2 · 上传(tar 经 SSH 管道直解压,不在本机留压缩包;pdb 调试文件不上传)

```bash
tar -C out/server -czf - --exclude='*.pdb' p2p-server libe_sqlite3.so appsettings.json wwwroot \
  | ssh root@<IP> "mkdir -p /opt/p2p/server && tar -C /opt/p2p/server -xzf -"
```

> 本次实测:产物约 107MB,传输+解压一步完成;目标目录 `/opt/p2p/server` 无需预建。

### 步骤 3 · 服务器侧配置(webBind + 可执行权限 + systemd unit + 启动)

```bash
ssh root@<IP> '
# Web 后台绑公网(M1 无监听无实际影响,M2 落地即生效;有顾虑可跳过保持 127.0.0.1)
sed -i "s/\"webBind\": \"127.0.0.1\"/\"webBind\": \"0.0.0.0\"/" /opt/p2p/server/appsettings.json
chmod +x /opt/p2p/server/p2p-server
# systemd unit(崩溃 5s 自愈 + 开机自启;WorkingDirectory 必须指向部署目录——数据库/日志均为相对路径)
printf "[Unit]\nDescription=P2P Server (control/STUN/web)\nAfter=network-online.target\nWants=network-online.target\n\n[Service]\nType=simple\nWorkingDirectory=/opt/p2p/server\nExecStart=/opt/p2p/server/p2p-server\nRestart=always\nRestartSec=5\n\n[Install]\nWantedBy=multi-user.target\n" > /etc/systemd/system/p2p-server.service
systemctl daemon-reload && systemctl enable --now p2p-server
'
```

### 步骤 4 · 服务器侧验证

```bash
ssh root@<IP> 'systemctl status p2p-server --no-pager | head -8'   # 期望 active (running),Memory ~60MB
ssh root@<IP> 'ss -lntup | grep p2p-server'                        # 期望且仅:0.0.0.0:7000(tcp) + 0.0.0.0:3478(udp)
ssh root@<IP> 'journalctl -u p2p-server --no-pager -n 10'          # 期望三行:「数据库就绪」「控制面监听 0.0.0.0:7000」「STUN-R 监听 0.0.0.0:3478/udp」「服务端启动完成」
ssh root@<IP> 'ls /opt/p2p/server/data /opt/p2p/server/logs'       # 首启自动生成 p2p.db(+wal/shm) 与 app-<日期>.log
```

### 步骤 5 · 云安全组放行 + 外网确认

控制台放行 **7000/TCP、3478/UDP**(其余端口见 §2,暂不放行),然后本机确认:

```bash
timeout 6 bash -c 'echo > /dev/tcp/<IP>/7000 && echo 可达' || echo 不可达
```

> UDP 3478 不能用"裸 STUN 探测无响应"判断连通:`stun_auth` 默认开启,未带 DEVICE-AUTH 的 Binding Request 会被服务端**静默丢弃**(02 §3.2 防御设计,本次实测即无响应)。正确姿势=服务器上 `tcpdump -ni any udp port 3478` 抓包 + 本机向 3478 发任意 UDP 包,看到 `In` 方向包即证安全组放行(本次 3/3 到达);端到端 STUN 响应须等客户端注册后带鉴权实测(A-1/A-3)。

### 本次实录的遗留事实(复用时注意)

- 安全组放行前外网 TCP 7000 不可达(已实测);服务侧 0.0.0.0 监听与安全组无关,可先完成全部服务器侧验证再放行。
- 首启自动建库并播种 admin/admin(07 §9 R6),正式使用须尽快改密;忘记密码用 §5 的 `--reset-admin`。
- `wwwroot/` 为 M2 Web 后台静态资源,M1 一并上传仅占位,不产生监听。
