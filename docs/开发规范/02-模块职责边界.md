# 02 · 模块职责边界

> 所属文档集：[README](README.md)　依据 [01 §2 解决方案结构](../技术设计文档/01-总体架构设计.md) 与 [05 关键模块设计](../技术设计文档/05-关键模块设计.md)。
> 目的：任何代码"归属于谁、能调用谁、禁止做什么"在本文件**唯一可查**。边界原则编号 MOD-x，供评审引用。

## 1. 六大边界原则

| # | 原则 | 内容 |
|---|---|---|
| MOD-1 | **单通道原则** | 客户端对服务端的控制协议消息（0x01~0x7E）**唯一出口是 ControlClient**；STUN(3478) 探测仅 Puncher；隧道/中继 socket 仅 TunnelHost（RelayClient 为其内部组件）。其余模块不得自开 socket 连服务端 |
| MOD-2 | **单一写者原则** | 映射状态唯一写者 MappingStateMachine；设备在线/能力唯一写者 DeviceRegistry（服务端）；relay 会话表唯一写者 RelayService；客户端本地文件唯一写者 StateStore。其他模块想改状态 → 发事件 |
| MOD-3 | **授权集中原则** | 授权判定唯一在服务端 Authorizer（L1~L3，05 §5）；客户端**不实现任何授权逻辑**，只执行服务端结论 + 本地设备级回退配置（peers.json）的开关作用 |
| MOD-4 | **加密集中原则** | 一切密码学原语只在 `Core/Crypto`；其余任何位置出现 `AesGcm`/`ECDiffieHellman`/`HKDF`/`HMACSHA256` 直接调用即违例 |
| MOD-5 | **持久化集中原则** | 服务端一切落库经 `Server/Data`（EF Core 仓储）；Web 层不绕过服务层直改 DbContext。客户端一切本地文件（state/settings/peers.json）经 StateStore 单写者 + 原子替换 |
| MOD-6 | **Core 纯净原则** | `P2P.Core` 零宿主引用、无静态可变全局状态、无 IO 副作用（日志经注入的抽象）；它是协议/算法的纯函数库 |

## 2. 模块卡片

每张卡：**职责**（做什么）/ **禁区**（明确不做）/ **依赖**（只许引用谁）。

### 2.1 P2P.Core（共享类库，无宿主依赖）

| 子模块 | 职责 | 禁区 |
|---|---|---|
| `Protocol/` | PCP 消息 record 定义（与 02 §2.4 消息表一一对应）、MessagePack 编解码、分帧常量、错误码常量 | 不含业务分支与状态机；不引用宿主；不做 IO |
| `Tunnel/` | PTP 帧编解码、counter 防重放窗口判定、channel 表数据模型、WINDOW 信用计算 | 不持有 socket；不做授权；不知道映射业务字段 |
| `Stun/` | RFC5389 子集报文编解码、DEVICE-AUTH 属性组包/校验 | 不发网络包；不查注册表 |
| `Crypto/` | ECDH(P-256)/HKDF-SHA256/AES-256-GCM/HMAC-SHA256 封装、ECIES、PTP 双重 ECDH 密钥派生 | 不落盘、不打日志、不含协议语义 |
| `Utils/` | Pipelines 分帧、重试/退避策略、日志与时间抽象 | 不含任何业务概念（业务工具放各宿主项目） |

依赖：无（不引用解决方案内任何项目）。

### 2.2 P2P.Nic（虚拟网卡封装）

- **职责**：创建/复用虚拟网卡、配置虚拟 IP、30s 自愈检测、卸载清理（`INicManager`，05 §1）；Windows 走 Wintun + IP Helper，Linux 走 TUN + rtnetlink。
- **禁区**：不做路由/转发/收发包（虚拟 IP 仅本地监听，TD-06）；不依赖控制通道；不知道映射存在；不含平台无关业务逻辑（公共部分放项目根，平台细节进 `Windows/`、`Linux/`）。
- 依赖：Core（仅 Utils）。

### 2.3 P2P.Server（服务端宿主）

| 模块 | 职责 | 禁区 |
|---|---|---|
| `Services/` ControlServer | TCP 7000 监听、每连接 ControlSession（握手/时钟对齐/seq-ts-HMAC 校验/消息分发）、DeviceRegistry、Authorizer L1~L3、SignalingCoordinator（OQ-11 会话协调）、0x75 失效推送 | 不做加密原语（调 Core/Crypto）；不直接暴露 HTTP；踢线/禁用联动只在此触发 |
| `Services/` StunService | 3478 UDP/TCP 收发、DEVICE-AUTH 校验、风暴防护四道闸（05 §7.1）、stun_dropped_total 计数 | 不解析 PCP 消息；不写业务库（仅内存缓存与计数器） |
| `Services/` RelayService | relay 会话表、8B 外层头剥离转发、空闲 90s 回收、令牌桶限速（M3） | **不解密/不解析密文帧**（TD-11）；不触发业务流程；不关心设备身份 |
| `Web/` ServerWebApi | 管理员 Minimal API、Cookie 会话、审计入口、仪表盘 | 不做业务判定（调 Services 服务层）；不直接拼协议消息 |
| `Data/` | DbContext、实体映射、迁移、仓储 | 不含业务规则（授权/心跳语义在 Services） |

依赖：Core。

### 2.4 P2P.Client（客户端宿主）

| 模块 | 职责 | 禁区 |
|---|---|---|
| ControlClient | 到服务端唯一控制通道：握手、RTT/2 时钟对齐、收发全部 PCP 消息、主备地址指数退避重连、能力模式切换 | 不含映射/打洞业务语义（只收发 + 事件投递）；不做超出 settings.json 的自主决策 |
| `Nic/` NicManager 宿主 | 调用 P2P.Nic、降级告警事件、卸载配合 | 平台 P/Invoke 不在此（在 P2P.Nic） |
| `Mapping/` | TcpListener/UdpClient 监听（绑虚拟 IP）、channel 分配、MappingStateMachine（唯一状态写者）、peers.json 读取、LAN 白名单对端校验（SEC-52 双保险一侧） | 不经其他路径发协议消息（一律经 ControlClient）；不直接调 Puncher（经 PunchScheduler 入队）；不碰隧道 socket 与加密 |
| `Punch/` | PunchScheduler（全局 FIFO 串行队列，OQ-11）+ Puncher（STUN 探测、UDP/TCP 对称打洞、Offsets 常量） | 不写映射状态（发 Puncher.Completed 事件）；中继回退决策不在打洞器（由状态机 + 设备级配置决定）；不与其他设备并发打洞 |
| `Tunnel/` | TunnelHost（设备对粒度会话表）、TunnelSession（收发循环/防重放/channel 分发）、RelayClient（中继路径接入）、REKEY 轮换 | 不做授权；不解析 channel 内业务载荷（只按 channelId 搬运）；不发起打洞（只报告路径死亡） |
| `Web/` LocalWebApi | 127.0.0.1:7100 HTTP + WS 推送 + 内嵌 SPA（TD-12 无鉴权，风险已接受） | 不直接操作 socket/网卡/文件；一切写操作转交对应模块公共接口 |
| StateStore | state.json / settings.json / peers.json 单写者、临时文件原子替换、损坏自愈 | 不做业务校验（格式校验在 08 §5 启动校验） |

依赖：Core、P2P.Nic。

### 2.5 前端 web/（pnpm workspace）

| 包 | 职责 | 禁区 |
|---|---|---|
| `ui-shared/` | 跨端复用资产：组件（StatusTag/RateChart/DeviceCard…）、composables（useApi/useWs/useRealtimeStats）、layouts、生成的 API 类型 | 不含页面与路由；不写死某一端的业务文案 |
| `client-app/` `server-app/` | 各自路由 + 页面装配 | 可复用组件一律上提 ui-shared；两 app 之间不互相引用 |

前端全局禁区：不拼协议消息、不直连 7000/3478（一切数据经 REST/WS）；WS 事件按 TD-16 处理（REST 是真相，状态类事件只触发 refetch）；API 路径用生成的常量，不手写字符串。

### 2.6 tests/

| 项目 | 范围 |
|---|---|
| P2P.Core.Tests | 协议编解码、加密、防重放、生成规则（09 §2.1） |
| P2P.Server.Tests | 控制服务、授权判定链、仓储 |
| P2P.Client.Tests | 映射引擎、状态机、哑节点约束 |
| P2P.IntegrationTests | 三进程互通、NatSimulator（09 §2.2） |

禁区：不测私有实现细节（测公共行为）；不修改产品代码迁就测试（AI-26）。

## 3. 依赖方向（引用规则）

```
P2P.Core      ←（被引用，自身零依赖）
P2P.Nic       ← Core
P2P.Server    ← Core
P2P.Client    ← Core、P2P.Nic
ui-shared     ←（前端被两 app 引用）
tests/*       ← 全部
```

🔴 禁止：任何反向引用（Core 引用宿主 = 结构性错误）；Server 引用 Client 或 Nic（服务端不装网卡）；Nic 引用 Server；两前端 app 互引；宿主项目之间互引（共享代码一律下沉 Core / ui-shared）。

## 4. 允许的调用与事件流

### 4.1 调用矩阵（跨模块**编译期**调用白名单）

| 调用方 | 允许调用 |
|---|---|
| Client.LocalWebApi | 各模块公共接口、StateStore（只读+受控写） |
| Client.Mapping | ControlClient（发 0x60/0x61/0x62/0x70 请求）、TunnelHost（OPEN/DATA/CLOSE）、PunchScheduler（入队）、事件总线 |
| Client.PunchScheduler | Puncher（串行执行）、事件总线 |
| Client.TunnelHost | Core/Tunnel、Core/Crypto、（内部 RelayClient）、事件总线 |
| Client.ControlClient | Core/Protocol、事件总线（信令事件投递 PunchScheduler/TunnelHost） |
| Server.Web | Services 服务层、Data 仓储（读） |
| Server.Services | Data 仓储、Core 全部、DeviceRegistry（ControlServer 内部） |
| Server.StunService | Core/Stun、Core/Crypto、DeviceRegistry 只读、计数器 |
| 前端 app | ui-shared、生成的类型常量 |

不在表内的调用路径 = 禁止，需要时先改本表（走规范修订）。

### 4.2 事件流（进程内总线，与 05 §9 保持同步）

| 事件 | 发布者 | 订阅者 | 类别（背压策略） |
|---|---|---|---|
| ControlClient.PunchInvited | ControlClient | PunchScheduler | 状态类（背压等待） |
| Puncher.Completed(result) | PunchScheduler | MappingStateMachine | 状态类 |
| TunnelHost.PathChanged | TunnelHost | MappingStateMachine + 统计 | 状态类 |
| MappingStateMachine.StateChanged | 状态机 | LocalWebApi（WS 推送）+ ControlClient（0x62） | 状态类 |
| StatsCounter.*（速率/字节） | TunnelHost/Mapping | LocalWebApi | 统计类（可丢弃+计数） |
| NicManager.Degraded | Nic 宿主 | LocalWebApi（告警） | 状态类 |

规则：跨模块协作**优先事件解耦**（尤其一切"通知对方改状态"的场景）；新增事件必须同时登记 05 §9 与本表并标注类别（AI-23）。

## 5. 违例判例（❌ → ✅）

| ❌ 违例写法 | 违反 | ✅ 正确做法 |
|---|---|---|
| MappingEngine 里 `Socket.Connect(server:7000)` 自己发 PunchRequest | MOD-1 | 经 ControlClient 发 0x70；打洞需求向 PunchScheduler 入队 |
| Puncher 失败后直接 `mapping.State = Failed` | MOD-2 | 发 `Puncher.Completed(failed)`，由状态机迁移 |
| LocalWebApi 里 `new AesGcm(...)` 加密配置文件 | MOD-4 | 调 `Core/Crypto`；本地文件本就无加密需求 |
| ServerWebApi 端点里直接改 `devices.Disabled=1` | MOD-5 | 调 Services 服务层（联动踢线 + 0x75 推送，05 §5） |
| RelayService 解开 PTP 帧头做按映射限速 | TD-11 / §2.3 禁区 | 中继只读 8B 会话头按会话限速；按映射计量在端上 |
| `Core/Protocol` 里 `File.WriteAllText` 缓存消息 | MOD-6 | Core 零 IO；缓存在宿主项目做 |
| Puncher 对两个目标同时打洞"提高吞吐" | OQ-11/05 §3.1 | 一切打洞经 PunchScheduler 串行队列 |
| Client 端点连上前先自行判断"我能不能访问对端" | MOD-3 | 客户端不判授权：发 0x70，服务端 Authorizer 判定 |
| 前端收到 mapping_state 事件直接改 store 状态字段 | TD-16 | 事件只触发 refetch，真相来自 REST |
| Server.Tests 里引用 P2P.Client 测授权链 | §3 依赖方向 | 授权链测试在 Server.Tests（或下沉 Core 后测 Core） |

## 6. 边界争议仲裁

拿不准代码归属时：按 §1 六原则推导 → 仍不确定 → **上报**（附候选方案与理由），不硬塞进"顺手"的目录。
