# 03 · 目录结构规范

> 所属文档集：[README](README.md)　目录树本体见 [01 §2 解决方案结构](../技术设计文档/01-总体架构设计.md)，本文定义**每个目录的功能范围（放什么 / 不放什么）、新文件归属判定、命名与文件约定**。规则编号 DIR-x。

## 1. 总则

| # | 等级 | 规则 |
|---|---|---|
| DIR-1 | 🔴 | 新文件必须落入 01 §2 既有目录；**新增目录 = 结构变更**，须先记 TD 决策再动手 |
| DIR-2 | 🟡 | C#：一个文件一个公共类型，文件名 = 主类型名；协议消息/DTO 可按消息族合并文件（如 `Messages.Control.cs`），但公共类型不跨文件散落 |
| DIR-3 | 🔴 | 仓库根目录只放：`AI-P2P.sln`、`Directory.Build.props`、`.editorconfig`、`.gitattributes`、`.gitignore`、`README.md`；不放任何代码与文档 |
| DIR-4 | 🔴 | 构建产物目录（`*/wwwroot`、`out/`、`dist/`、`node_modules/`）不手改、不入库 |

## 3. 新文件归属决策树

```
新文件是什么？
├─ 跨端（Client+Server）共享的纯逻辑/类型？
│   ├─ 协议消息/错误码 → src/P2P.Core/Protocol/
│   ├─ 隧道帧/channel 模型 → src/P2P.Core/Tunnel/
│   ├─ STUN 报文 → src/P2P.Core/Stun/
│   ├─ 加密/密钥 → src/P2P.Core/Crypto/
│   └─ 通用工具 → src/P2P.Core/Utils/（含业务概念 → 放宿主，Core 不收）
├─ 虚拟网卡平台细节？
│   └─ src/P2P.Nic/{Windows|Linux}/（公共部分在 Nic 项目根）
├─ 只在服务端运行？
│   ├─ 协议服务/授权/信令 → src/P2P.Server/Services/
│   ├─ HTTP 端点 → src/P2P.Server/Web/
│   └─ 落库/迁移 → src/P2P.Server/Data/
├─ 只在客户端运行？
│   └─ src/P2P.Client/{Nic|Mapping|Punch|Tunnel|Web}/ 按域（§2 表）
├─ 浏览器代码？
│   ├─ 两端复用 → web/ui-shared/
│   └─ 单端页面 → web/{client-app|server-app}/
├─ 测试？
│   └─ tests/ 对应项目（被测项目是谁就进谁的 Tests）
└─ 打包/CI 脚本？
    └─ build/
```

判定仍有冲突：按 [02 §1 边界原则](02-模块职责边界.md) 推导；仍不定 → 上报（02 §6）。

## 4. 命名约定

| 对象 | 约定 | 示例 |
|---|---|---|
| C# 类型/文件 | PascalCase，文件名 = 主类型名 | `PunchScheduler.cs` |
| 协议消息 record | 与 02 §2.4 消息名一致 | `Register` / `RegisterAck` / `PunchInvite` |
| msgType 常量 | 集中一处，值 = 02 §2.4 | `MsgType.Register = 0x10` |
| 错误码常量 | 集中 Core/Protocol，值 = 04 §5 | `ErrorCode.DeviceActive = 4004` |
| 事件 | `XxxCompleted` / `XxxChanged`（05 §9 登记） | `PuncherCompleted` |
| 服务端配置键（库内） | snake_case（03 §2.8） | `punch_retention_days` |
| 配置文件键 | appsettings 分节 camelCase；settings.json camelCase（08 §5） | `serverAddrs` |
| 本地 JSON 字段 | camelCase（03 §5） | `relayFallback` |
| 数据库表/列 | 蛇形（03 §2） | `owner_device_id` |
| 测试 | 类 `XxxTests`；方法 `Method_Scenario_Expected` | `Offsets_N3_ReturnsOffset2` |
| 前端组件 | PascalCase；composable/store `useXxx` / `useXxxStore` | `DeviceCard.vue` / `useWs` |
| TS 类型 | 由 `export-ts` 生成（06 §5），**禁止手改 `api.d.ts`** | — |
| 魔数 | 禁止字面量散落：协议常量进 Core、可配参数走配置键 | `Puncher.Offsets`（05 §3） |

## 5. 文件与编码

| # | 等级 | 规则 |
|---|---|---|
| DIR-5 | 🟡 | 全库 UTF-8（无 BOM）、LF 行尾、文件保留末尾空行；`.gitattributes` 声明（`* text=auto eol=lf`），杜绝 Windows 开发混入 CRLF |
| DIR-6 | 🟡 | 一次改动不跨无关文件（与 AI-09 呼应）；生成文件（api.d.ts、迁移文件）提交前 `dotnet format`/`pnpm lint` 过一遍 |
| DIR-7 | 🟢 | 超过 ~500 行的实现文件考虑拆分（状态机/收发循环天然大者除外） |

## 6. 与构建的衔接

- `Directory.Build.props`：统一 `net10.0`、`Nullable=enable`、`ImplicitUsings=enable`（AI-01）；
- SPA 产物经 vite `outDir` 直写两宿主 `wwwroot`（08 §2），CI 在 publish 前先跑 `pnpm build` + `export-ts`；
- `docs/deploy/`、`docs/manual/` 于 M4 创建（08 §8），此前不预建空目录。
