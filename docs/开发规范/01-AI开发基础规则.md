# 01 · AI 开发基础规则

> 所属文档集：[README](README.md)　规则编号 AI-xx，供任务指令、代码评审与提交记录引用。
> 每条规则针对一类**已知的 AI 自动开发失效模式**——不是通用编码风格指南。

## 0. 最高原则（先于一切规则）

1. **文档说了算**：行为、参数、命名、错误码一律以 PRD v0.4 / 技术设计 v1.6 为准；文档没写的 = 未决问题，上报提问，不自行发明。
2. **不确定即停**：任何"我认为应该是"的推断，只要影响外部可见行为（协议字节、存储结构、API 形状、UI 文案、错误码），停下来问，不赌。
3. **如实报告**：未完成就说未完成；测试失败要带原始输出报告；禁止用"理论上可以""应该没问题"冒充已验证。

### 2.1 参数登记表（用户决议值 · 只读引用）

> 本表是设计文档的**引用副本**，冲突时以设计文档为准；发现不一致按 AI-08 上报。

| 参数 | 值 | 出处 |
|---|---|---|
| TCP 打洞并发 N | 1~5，默认 3；目标端口 = STUN 端口 + (N−1)；双方同一次打洞同一 N | OQ-1 / TD-13，02 §5.2 |
| UDP channel | 双向空闲 60s 回收；每 UDP 映射并发上限 256 | TD-15，05 §2.4 |
| STUN 风暴防护 | 单 IP 50pps（突发 100）/ TCP 每 IP 并发 ≤4；每设备 10QPS；全局 2000pps 熔断 5s | TD-18，05 §7.1 |
| 时钟对齐 | RTT/2 补偿算 offset；±120s 窗口；5005 超窗重校准后**仅重试一次** | OQ-12，02 §2.3 |
| 周期 | 控制心跳 30s；隧道 KEEPALIVE 20s；中继空闲回收 90s；中继态回切直连重试 60s；隧道空闲回收 300s | 02 §2.4/§4.2/§6.2/§4.5 |
| 虚拟网段 | 100.64.0.0/24 可配；统一下发固定主机位 .2（各设备同值） | OQ-2/13，03 §4 |
| 远程码 | 6 位，字符集 0-9 + a/b/c，纯数字空间优先 | OQ-8，03 §3 |
| 邀请码 | 6 位去混淆：数字 2-9 + 小写字母去 o/i/l（31 字符）；全局唯一 | OQ-17，03 §3 |
| 保留期 | audit_logs / punch_stats 均 90 天 | OQ-17，03 §2.7/§2.9 |
| 帧上限 | 控制帧 body ≤ 64KiB；隧道 TCP DATA ≤ 16KiB；UDP 承载帧 ≤ 1400B | 02 §2.1/§4.3 |
| 端口 | 控 7000/TCP；STUN 3478/UDP+TCP；中继 7010+；服务端 Web 7500（127.0.0.1）；客户端 Web 7100（127.0.0.1） | TD-07 |
| 事件总线 | 每消费者有界 Channel 容量 1024 | TD-14，05 §0 |

## 3. 一致性（防漂移）

| # | 等级 | 规则 |
|---|---|---|
| AI-11 | 🔴 | 术语以 PRD 术语表为准，代码标识符按下表，**禁止发明同义词**（本项目真实事故：relay_fallback 迁移后残留 4 处旧词） |
| AI-12 | 🔴 | **三视图同步律**：协议消息字段 ↔ 表结构列 ↔ API 字段是一个实体的三个投影，改任何一处必查其余两处（02 / 03 / 04） |
| AI-13 | 🔴 | 冻结清单不得改动字段位置与语义：`Hello.protocolVersion`、`UpdateInfoRequest`、既有消息只允许"新增 msgType / 新增可选字段"（02 §7） |
| AI-14 | 🔴 | 错误码唯一来源是 04 §5 总表：只增码不改义；代码/文档引用的每个码必须存在于总表 |
| AI-15 | 🔴 | 改名/删除/迁移任何字段、配置、错误码、消息后，对**旧名 + 同义词 + 相关数字上限**做全库 grep，命中处逐一判定"新表述 / 修订记录历史注记 / 漏改" |
| AI-16 | 🔴 | 改变设计语义的提交必须三处回写：设计文档正文 + README 修订记录 + 追溯矩阵行；只改代码不改文档 = 未完成 |

**术语 → 代码标识符对照**：

| 术语（中文） | 标识符 | 禁止的同义词 |
|---|---|---|
| 设备 | `Device` | node/machine/peer（peer 仅用于"对端设备"语境 `peerDeviceId`） |
| 远程码 | `remoteCode` | code/token/pin |
| 虚拟 IP | `virtualIp` | tunIp/innerIp |
| 映射 | `Mapping` | forward/rule/tunnel |
| 哑节点（能力模式） | `passive`（对 `normal`） | mute/dumb/readOnly |
| 开放内网段 | `lanSegment`（cidr） | whitelist/allowedNet |
| 隧道 / 通道 | `Tunnel` / `channel`（隧道内复用流） | 不混用；channel ≠ 隧道 |
| 中继回退（设备级配置） | `relayFallback`（peers.json） | fallback/relayEnabled |
| 访问方 / 服务方 | `ownerDeviceId` / `targetDeviceId` | client/server（避免与进程名混淆） |
| 打洞并发路数 | `N`（punchConcurrency） | attempts/retries |

## 4. 安全红线

| # | 等级 | 规则 |
|---|---|---|
| AI-17 | 🔴 | **秘密零日志**：deviceSecret、静态/临时私钥、用户密码、ECIES 明文不进日志、异常消息、dump；remoteCode 日志只出后 2 位 |
| AI-18 | 🔴 | 加密唯一入口 `Core/Crypto`（MOD-4）；算法与参数固定（ECDH P-256 / HKDF-SHA256 / AES-256-GCM / HMAC-SHA256），任何地方出现散落的加密原语调用即违例 |
| AI-19 | 🔴 | 异常不吞：禁止空 catch、禁止 catch 后仅记日志继续；协议路径按 02 错误码回 Error；进程未捕获异常落日志后**快速失败**交给系统拉起（01 §4.2），不带病运行 |
| AI-20 | 🔴 | 授权执行点不可省略：L1~L3 服务端判定 + 对端 lan_segments 白名单双保险（SEC-52/53）；客户端不得"优化掉"任何一处重复校验 |
| AI-21 | 🟡 | 日志结构化字段按 08 §6（sessionId/mappingId/channelId/deviceId…），便于日志页过滤 |

## 5. 并发纪律（TD-14 落地）

| # | 等级 | 规则 |
|---|---|---|
| AI-22 | 🔴 | 跨组件共享可变状态**仅三处白名单**（DeviceRegistry / RelaySessionTable / Interlocked 计数器）；禁止新增 `lock`；复合原子操作进 Actor 队列或不可变快照（05 §0） |
| AI-23 | 🔴 | 事件总线每消费者有界 Channel(1024)：状态类事件背压等待、统计类丢弃+计数；**新增事件必须登记 05 §9 并标注类别** |
| AI-24 | 🔴 | async 纪律：禁止 `.Result`/`.Wait()`/`GetAwaiter().GetResult()`；CancellationToken 全链贯穿；I/O 循环不执行业务逻辑，解析完即投递 Actor |
| AI-25 | 🔴 | 优雅停机顺序不可颠倒：PunchScheduler 停止入队 → 状态机排空 → 隧道排水关闭 → 控制通道最后关（05 §0 纪律 5） |

### 7.2 交付自检清单（每项任务结束前逐项执行）

```
[ ] 1. 本任务每个改动都有 FR/TD/OQ/D 编号依据（AI-06）
[ ] 2. dotnet build 零 error；warning 逐条处理或说明（新代码不留新 warning）
[ ] 3. dotnet test 全过；失败项已在报告如实列出（最高原则 3）
[ ] 4. 若动了消息/表列/API 字段：三视图三处已核对（AI-12）

[ ] 10. 新文件落在 03 规范的既有目录（DIR-1）
```
