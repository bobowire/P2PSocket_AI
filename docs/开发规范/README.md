# 开发规范 · P2P 内网穿透产品

> 版本：v1.0　创建日期：2026-08-20
> 依据：[PRD v0.4](../prd/README.md)（D1~D21、OQ-1~17）+ [技术设计 v1.6](../技术设计文档/README.md)（TD-01~18）
> 定位：编码阶段的**约束层**——PRD 定"做什么"，技术设计定"怎么设计"，本规范定"怎么写、写在哪、什么不许做"。
> 适用对象：全部由 AI 自动完成的开发任务（人工开发同样适用）。

## 优先级链（冲突时高位获胜）

```
PRD（需求） > 技术设计文档（v1.6） > 本开发规范 > AI/个人判断
```

任何两层发生冲突：**停止编码，按文档缺陷上报**（回 PRD 走 OQ 流程），不得自行仲裁、不得就近取舍。

## 约束等级

| 标记 | 含义 |
|---|---|
| 🔴 强制 | 违反即缺陷，交付前必须消除 |
| 🟡 约定 | 团队一致性要求，违反须在提交说明中写明理由 |
| 🟢 建议 | 质量倾向，鼓励遵守 |

## 维护规则

1. 本规范修订同样走记录：改动写入下方修订记录；
2. 规范与技术设计冲突时以设计文档为准，并立即上报修正规范（规范是衍生层，不是第二事实源）；
3. 编码过程中沉淀的新规则（真实踩坑）应回流进对应编号段，规则只增不删（废弃标记 ~~删除线~~ 保留原文）。
