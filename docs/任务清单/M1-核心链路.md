# M1 · 核心链路可用 · 任务清单

> 所属文档集：[README](README.md)　创建：2026-08-20　状态：☐ 未开始
> **目标**：两台设备完成注册并建立第一条 UDP 直连映射（TCP 打洞/中继/分组管理全量在 M2）。
> **出口标准**：验收场景 **A-1 首启注册 / A-2 登录与发现 / A-3 UDP 打洞直连 / A-4 本地监听隔离** 全部通过（PRD 09 §2）。
> 需求范围：FR-S-101/102/104/106、201/202、301/302、401/501/502、601；FR-C-101~103、201、301/302/304/305/306、401、501、601/602、801~804、901~903。
> 任务执行受 [开发规范](../开发规范/README.md) 约束；状态图例与使用规则见清单 README。

## 0. 依赖总览（泳道并行建议）

```
阶段0 骨架(M1-01~03)
 ├─▶ 阶段1 Core(M1-04~10) ──┬─▶ 阶段2 服务端(M1-11~19)
 │                          └─▶ 阶段3 客户端(M1-20~30)   ← 服务端与客户端可并行（协议消息为准绳）
 └─▶ 阶段4 前端(M1-31~33，仅依赖 M1-03 与 API 契约；MSW 解耦后端进度）
                              阶段5 集成验收(M1-34~37) ← 全部完成后
```

关键串行链：**M1-05 Crypto → M1-09 PTP → M1-25/26/27（客户端隧道/打洞/映射）→ M1-35 A-3**；
**M1-06/07 协议 → M1-13 会话 → M1-14 注册 → M1-24 客户端注册 → M1-37 A-1**。

### A-3 失败详情（Win-1 轮，2026-09-11~12）

**环境**：服务端=腾讯云 Debian（139.155.70.54）；A=Windows 本机（出口 27.19.230.104，NAT=PortRestrictedCone）；B=Windows 异地机（10.4.125.6 内网，出口漂移 27.17.60.146/113.57.21.152，NAT=Symmetric，运营商 CGNAT）。

**现象**：映射「远程桌面」7801→B:3389，状态 failed/detail=punch_timeout（10s），多次 retry 复现。

**排查（四环节逐一验证，全部正常）**：
1. STUN 探测（双侧）——服务端 tcpdump：A/B 探测包均达、均获响应（96B 请求/32B 响应）；
2. 两段式信令——A 收到延后 Ack 携带 B 端点 27.17.60.146:61187（0x70/0x71/0x76 链路完好，B 探测仅晚 A 76ms）；
3. A→B 出站——A 机 pktmon：THello1×60（20×3 组）正常离开网卡；
4. 防火墙（双侧）——均已添加 p2p-client.exe UDP 入站放行规则并核实存在。

**根因**：A 机 pktmon 抓包 25s 零对端入站——B 的 THello1 从未到达 A 网卡。B 为 Symmetric：向 A 回射时源端口≠STUN 上报的 61187，被 A 侧 PortRestrictedCone 按精确端口匹配丢弃。Symmetric×锥形为单端点策略不可穿透组合。

**处置**：非协议缺陷，不进缺陷队列；该组合属 M2 SymmetricSequential（多端点端口猜测）+ TCP 桥接 + 中继回退设计目标。A-3 真机穿透确认顺延至 M2（或后续换网络组合复验，如蜂窝热点侧 NAT 常为锥形）。双侧证据留存：服务端 /tmp/punch-trace.txt、A 机 D:\P2PClient\pkt.txt、NatTypeTester 双侧输出（工具 D:\NatTypeTester）。

### A-4 过程记录（Win-1 轮，2026-09-12）

**发现 M1 缺陷（已修复）——映射监听绑定地址错误**：向导路径装机的客户端（先装服务后注册），注册完成后映射监听一直绑 **127.0.0.1** 而非虚拟 IP 100.64.0.2（违反 01 §3.2），与本地同端口服务相撞报 `listen_failed: AddressAlreadyInUse`。根因：ClientRuntime 冷启动装配引擎时 VirtualIp 尚空（未注册），绑定地址降级 Loopback；向导注册完成后 `RunRegisteredPathAsync` 应用网卡但从不切换引擎绑定地址。集成测试未覆盖此路径（A-1 只测注册、A-3/A-4 用预置已注册 state 构造直接走已注册分支）。修复：MappingEngine 增 `UpdateVirtualIp()`（注册完成时点必然无已启用映射，只影响后续新监听），注册后路径在 Nic 应用前切换；引擎级回归用例 = UpdateVirtualIp 后新监听绑新地址且与回环同端口占位 echo 并存互不干扰（96/96 过）。

**验证结果（半版）**：修复部署后 retry 映射 → `100.64.0.2:8080 LISTENING`（p2p-client 进程）；再启占位 `127.0.0.1:8080` → **双监听并存**；curl 127.0.0.1:8080 返回 `A-LOCAL-8080`（占位不受影响）；curl 100.64.0.2:8080 连接建立后被引擎关闭（映射监听真实存在且 accept，无隧道按设计拒绝）。打洞按 A-3 同因落 failed/punch_timeout（预期）。完整版（A 经虚拟 IP 访问 B 侧内容）待 B 换网络补跑。

**遗留观察（M2 自愈候选）**：服务重启瞬间恢复映射曾报 `listen_failed: AddressNotAvailable`（Wintun 适配器刚经历进程切换、IP 尚未对 TCP 栈生效的窗口），retry 即恢复——重启后监听失败自动重试属恢复健壮性，记 M2。
