# M7 · 设备级优先打洞与交替重试 · 任务清单

> 所属文档集：[README](README.md)　创建：2026-11-19　状态：✅ 收官（2026-11-20，M7-01~06 全 ✅；立项 2026-11-19，设计 12 号 v0.2 决策点 5/5 批复；PRD v0.17 回流完成）
> **目标**：打洞承载决策权从映射级上收**目标设备级本地配置 punchMode**（TCP/KCP 切换，默认 TCP，peers.json 本地真相）——首次打洞按优先模式执行；中继回退后 60s 回切重试以优先模式为起点 **TCP/KCP 交替**；**Failed 态纳入同一周期循环自动重试**（无人值守自愈）；打洞成功/失败日志标注承载；设备发现页新增"优先打洞模式"开关与"隧道类型"列（四态）。控制协议 0x70~0x78 / 服务端 / punch_stats 统计口径零变更（PRD NET-78 · 技术设计 12 号 v0.2 · TD-30 · FR-C-405/803 扩展）。
> **出口标准**：技术设计 [12 §10](../技术设计文档/12-设备级优先打洞模式与交替重试设计.md) 测试口径三线全绿——①单测（PeersStore 双字段容错/Planner 交替序列含执行层映射断言/Scheduler 出队决策同对合并不跳号/TunnelSession.Bearer 四态）；②集成（中继回切交替 0x70 proto 序列红绿、Failed 周期自愈、PeersApi 新形状、tunnels.bearer）；③前端（Devices 两新列+诊断页承载细化）——＋五套件回归全绿（Core/Nic/Client/Server/Integration 串行）＋编译 0 警 0 错＋ExportTs 再生 api.d.ts diff 仅 TunnelView.Bearer 一处。
> **立项背景**：现状打洞协议由"首条触发映射的 proto"决定（02 §4.5）——同一设备对多映射可各自声明不同 proto、实际生效不可预期；中继回切 60s 重试协议恒定，若恰为本网络不可打洞形态（对称 NAT 下 UDP 互发端点过期必败，而 TCP 扇形端口预测恰为对称 NAT 设计反而有机会）将永远在同一形态循环失败；Failed 态无自动重试（7×24 无人值守"一次失败=永久失败"）；四型结果日志无协议标注；设备页无隧道形态呈现。用户指令 2026-11-19（优先协议切换+失败回退中继+重试交替+日志完善+隧道类型列），同日 v0.2 修正：切换语义为 **TCP/KCP**（kcp=UDP 打洞+KCP 承载优先，口径分层见设计 12 §2.1——配置层 tcp/kcp、执行/统计层 tcp/udp 不变）。
> **决议**（2026-11-19，5/5）：① **设备级完全接管**——打洞协议一律按设备页 punchMode（值域 tcp/kcp 默认 tcp），映射 proto 字段保留存档不再决定打洞（否决"未设置跟随映射"三态割裂与"映射优先"两案；存量部署首打协议统一变 tcp=已知悉接受的行为变更）；② **交替以优先模式为起点**（tcp→kcp→tcp… / kcp→tcp→kcp…；手动重试/映射启用/断链=新序列从头，仅周期重试消耗交替序列）；③ **Failed 态纳入 60s 周期循环**（与中继回切共用 PunchRetryLoop；仅重排打洞——Failed+有监听走 EnqueueRetry，无监听失败仍归 M2-24 监听重试集防双驱动叠加）；④ 打洞日志协议化（PunchOutcome.Proto 执行层口径，A/B 两侧结果线统一 proto= 标注）；⑤ 设备页隧道类型列（TunnelSession.Bearer 四态 relay/kcp/raw-udp/tcp；ClientReporter.BearerFor 三态上报口径不动——展示与统计解耦）。
> 任务执行受 [开发规范](../开发规范/README.md) 约束；状态图例与使用规则见清单 README。
