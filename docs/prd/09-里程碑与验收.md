## 2. 验收场景

| # | 场景 | 前置 | 预期 |
|---|---|---|---|
| A-1 | 首启注册 | 全新 Windows + Linux 客户端，服务端就绪 | 浏览器自动打开向导；选默认分组注册成功；虚拟网卡创建且获得虚拟 IP；服务端可见设备在线 |
| A-2 | 登录与发现 | alice 在两台设备登录 | 双方设备列表互见（同账号），字段完整（远程码/虚拟 IP/状态） |
| A-3 | UDP 打洞直连 | 两客户端位于不同 NAT（至少一方锥形 NAT） | 映射建立显示"直连"；TCP 服务（如 SSH）经 `虚拟IP:本地端口` 可访问且数据完整 |
| A-4 | 本地监听隔离 | 本机 127.0.0.1:8080 已有服务 | 在虚拟 IP:8080 建映射后两者并存互不干扰 |
| A-5 | TCP 打洞（端口预测） | 双方 NAT 对 TCP 做端口转换 | STUN(TCP) 获取端口后按并发路数 N（默认 3，目标端口 +2）命中；调整 N=1~5 对比命中率并进基准报告 |
| A-6 | 中继回退 | 双方对称 NAT（打洞必失败）；目标设备 B 开启回退、目标设备 C 关闭 | B 的映射自动进入"中继"仍可访问；C 的映射显示"失败" |
| A-7 | 授权拒绝 | 未登录哑节点尝试创建映射/查询列表 | 本地入口置灰；直连服务端 API 亦被拒绝且记审计日志 |
| A-8 | 内网段白名单 | 对端开放 192.168.1.0/24 | 白名单内 NAS 可映射访问；未开放网段的目标被服务端拒绝；移除白名单后存量映射即失效 |
| A-9 | 远程码重置 | 存量映射引用旧码 | 重置后旧码立即失效，映射标记失效提示；新码可重新配置 |
| A-10 | 服务健壮性 | kill 客户端进程 / 重启机器 | 服务自动重启/自启，网卡与映射状态恢复，控制通道自动重连 |
| A-11 | 卸载清理 | 卸载客户端 | 虚拟网卡与驱动残留清除，配置目录按用户选择保留或删除 |
| A-12 | 服务端 Web 远程接入 | 服务端机器部署客户端（F7 流程） | 管理员经映射访问服务端 Web 全功能可用；服务端 Web 端口从公网扫描不可达 |
| A-13 | 注册准入三重闸门 | `device_registration_open=0`；同 IP 高频注册；设备数达 `max_devices` | 三种情形注册均被拒且审计留痕；开关=1 时正常注册不受影响（覆盖式恢复同受闸门约束——③设备数上限对覆盖式恢复=查而不拦，仅拦新增行，技术设计 07 §5.1） |
| A-14 | 注册入组遵循审批策略 | 默认分组策略=approval，新设备注册 | 注册成功但进入待审队列（对组内设备不可见），管理员批准后可见；策略=free 时行为不变 |
| A-15 | 登录防爆破 | 0x21 连续错误密码；admin Web change-password 连续错误旧密码 | 失败次数递增延迟（封顶值内），期间正确登录同样受延迟；触发与解除均审计；低频正常失败不受影响 |
| A-16 | 密码字段加密传输 | 抓包 0x20/0x21/0x23 控制信道报文 | 报文中无明文密码（ECIES 密文）；新旧客户端混布行为符合 OQ-21 硬切口径（服务端拒收明文、无过渡双轨） |
| A-17 | 告警与安全中心 | 制造登录失败风暴＋新设备注册 | webhook 收到阈值告警；安全中心展示聚合计数并可一键封禁来源 IP（封禁后该 IP 四个监听面均不可达，解封恢复） |
| A-18 | 平台加固生效 | 服务端以专用非特权账户运行；本机无 token 的进程访问客户端本地 API | 服务非 root 正常履职（含 3478 低端口监听）；本地 API 未携带 token 的请求被拒，向导/页面正常流程不受影响 |

## 3. 开放问题决议记录（2026-08-19 评审，OQ-1~OQ-9 关闭；同日第三轮技术设计审查追加决议 OQ-10~OQ-17；2026-08-20 M1 任务清单完整性检查追加决议 OQ-18；2026-09-12 M2 任务清单编制追加决议 OQ-19；2026-10-21 M5 立项决议 OQ-20；2026-10-22 M5 开工口径 OQ-21、同日 M5-01 走查回流 OQ-22）

| # | 问题 | 决议 |
|---|---|---|
| OQ-1 | TCP 打洞偏移与并发策略 | 扩展为可配置：配置项"**打洞并发路数 N**"（默认 3，范围 1~5）；N 条并发连接的目标端口统一为 STUN 公网端口 **+(N−1)**——N=1 直接连 STUN 端口（+0）、N=2 双方连接的端口 +1、依次类推、最大 +4 |
| OQ-2 | 虚拟网段默认值 | 默认 **100.64.0.0/24**，保留配置项 |
| OQ-3 | 初始管理员产生方式 | 服务端内置默认账号 **admin / admin**，首次登录提示修改密码（FR-S-203） |
| OQ-4 | 中继 TCP 承载 | 随 M2/P1 一并实现（FR-S-704） |
| OQ-5 | 客户端自动升级 | 不做自动升级；当协议不被支持时自动打开浏览器展示升级提示页，页面内容从服务端获取、本地展示（FR-C-904 / FR-S-804） |
| OQ-6 | 映射协议是否支持 UDP | 支持，P1（FR-C-303） |
| OQ-7 | 中继回切策略 | 中继状态下每 **60s** 重试直连；切换须"先排水后切换"——处理完上一通道在途数据后新通道再响应，避免数据顺序问题（NET-75） |
| OQ-8 | 远程码格式 | **6 位字符**，字符集为数字 0-9 与字母 a、b、c；纯数字组合（10⁶）用完之前不启用字母，之后扩展至全字符集（13⁶ ≈ 483 万）（FR-S-901） |
| OQ-9 | 控制通道与服务端 Web 可选 TLS | 现阶段不引入，维持全 HTTP（风险 R1 已知情接受） |
| OQ-10 | 中继回退配置粒度 | 由逐映射改为**目标设备层级**：本机对每个目标设备一份 `{relayFallback}` 配置，其下全部映射共用（D3 修订、FR-S-702/FR-C-304/FR-C-803 同步） |
| OQ-11 | 打洞并发多目标时的端口预测污染 | 客户端全局**串行打洞队列**：上一会话完成/超时后再执行下一个；服务端同时保证同一目标设备至多一个活跃打洞会话（并发申请排队/合并） |
| OQ-12 | 控制通道时钟偏差死锁 | Hello 阶段不校时间戳；HelloAck 携带服务器时间，客户端按 **RTT/2 补偿传输耗时**计算 offset 后再发后续消息；超窗返回 TIME_SKEW 供重校准重试 |
| OQ-13 | 虚拟 IP 唯一性 | 取消全局唯一：虚拟 IP 仅作本机监听地址、不参与跨机寻址，服务端统一下发网段内固定地址（默认 .2），无池上限、无回收 |
| OQ-14 | 凭据丢失后的重注册 | 同 MAC 识别码再注册 = **覆盖式恢复**（保留设备 ID/远程码/归属/分组成员资格，重签设备凭据，存量映射不失效）；原设备在线时拒绝、需管理员解绑（防伪造 MAC 抢注） |
| OQ-15 | 注册响应明文下发设备凭据 | RegisterAck 的 deviceSecret 改用客户端静态公钥 **ECIES 加密下发**（防注册链路窃听）；注册期公钥替换的 MITM 窗口攻击记录为残余风险 R7 |
| OQ-16 | 设备列表消息超单帧上限 | 0x40 采用应用层分页（offset/limit → total/items/hasMore），客户端循环拉全量 |
| OQ-17 | 邀请码生成规则 / 打洞统计保留期 | 邀请码随机 **6 位**（去混淆字符集）**全局唯一、不重复**，撤销即失效；打洞统计保留 **90 天**，与操作审计一致 |
| OQ-18 | 打洞端点互换时序无协议载体（设计缺口：被动方在收到邀请前无 STUN 探测动机，0x70/0x71 均未定义端点生产者，与"STUN 映射不长持"互相矛盾） | **两段式编排**（纯设计层决议，PRD 各 FR 正文无改动）：发起方端点随 0x70 上送；0x71 邀请被访问方并携带发起方端点；被访问方即时 STUN 探测、经新增 0x76 PunchEndpoint 回传、随即不等中转直接开始发包；服务端以 0x70 Ack 向发起方送达对端端点；目标离线/邀请不可达 → 新错误码 4005 TARGET_OFFLINE（技术设计 v1.7 / TD-19） |
| OQ-19 | TCP 打洞并发路数 N 无上送载体（设计缺口：TD-13 要求 N 取发起方客户端配置、经 PunchInvite 统一下发且双方同一 N，但 0x70 PunchRequest 载荷未定义 N 字段，服务端无从得知发起方配置，实现中硬编码 3） | **0x70 PunchRequest 增可选字段 `punchConcurrency`（int，1~5）**（纯协议层决议，PRD 各 FR 正文无改动）：发起方随 0x70 上送本地配置 N（缺省 3），服务端校验范围后经 0x71 PunchInvite 与 0x70 Ack 统一回填下发，双方该次打洞执行同一 N——补全 TD-13 的 N 通路，符合协议"仅新增可选字段"演进规则（技术设计 v1.8 / TD-20） |
| OQ-20 | M5 安全加固立项决议（2026-10-21 全量安全评估回流：控制信道登录族密码明文传输 / 开放设备注册硬编码直入默认分组[设计文档声称的 max_devices 与单 IP 注册频控未实施的漂移同查实] / 0x21 登录零防爆破为 P0 三项；检测响应层缺失——审计与处置动作齐备但无告警通道与准入闸门） | ①里程碑范围＝**三阶段全量**（P0 修复＋监测响应闭环＋平台加固）；②密码明文修复走**登录字段 ECIES 化**（沿 OQ-15 模式，D21「不引入 TLS」维持不动，控制信道元数据明文留在 R1 知情接受范围）；③新增 `device_registration_open` 开关**默认开放**（兼容现状，管理员按需关闭；配合单 IP 频控＋max_devices 实施收敛风险）；④管理端 TOTP 双因素**不纳入 M5**、记入待办池 |
| OQ-21 | M5 开工前三项口径确认（2026-10-22 用户批复：ECIES 混布升级窗口 / 发布产物签名 / 告警 webhook 接收端） | ①**ECIES 混布升级窗口＝硬切**：升级后服务端不设明文过渡双轨，旧客户端明文登录一律失败（未升级的自有设备与陌生旧设备均须升级后方可登录）；自家机队按「先客户端、后服务端」单一维护窗口执行升级；客户端对未升级旧服务端的行为（拒绝并提示升级[D17 既有口径] vs 能力回退明文）由 M5-01 技术设计定案；②**发布产物签名＝降级哈希核验**：无代码签名证书且不购入，SEC-84 预授权口径生效——SHA-256 哈希清单核验＋手册指引；③**告警 webhook＝通用 JSON、暂不接厂商**：暂无接收端，告警载荷为通用 HTTP POST JSON 并预留扩展位，不做企业微信/钉钉等厂商消息格式适配 |
| OQ-22 | M5-01 设计走查回流三项口径（2026-10-22，tech-design-reviewer 四分类清单 P1 两项经用户裁定+随批注记） | ①SEC-73「命中可审计」细化＝**命中以 per-面计数器可观测（安全中心呈现），处置动作（ip_block/ip_unblock/ip_auto_block）入审计**——不逐条写命中审计行（封禁期逐包写审计=自我 DoS 向量；用户选 A=认可设计口径）；②SEC-83 缺钥降级注记＝**masterKey 缺失不阻断启动、加密不启用**（ERROR 日志+管理页横幅；存量部署升级不断服，库文件权限仍为首道防线，补配后启动迁移自动完成）——**不可解密文行处置**（配错钥且无有效 prev）=该行凭据视为失效走解绑重注册+ERROR 计数（技术设计 07 §14.3 走查补段）；③SEC-71 措辞修正＝告警登录失败源为**登录族四入口聚合**（0x21/0x23/admin 登录/admin 改密，SEC-63 共享计数的自然超集，原「0x21 与 admin 双源」字面过窄） |
