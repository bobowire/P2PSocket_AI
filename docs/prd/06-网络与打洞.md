# 06 · 网络与打洞

> 所属文档集：[README](README.md)　编号前缀：NET

## 1. 虚拟网卡与虚拟 IP（决策 D2）

| 项 | 约定 |
|---|---|
| 目的 | 为每台客户端提供**独立于本机现有地址**的本地监听地址空间：映射监听端口绑定在虚拟 IP 上，不与本机 127.0.0.1 / 物理网卡上的同端口服务冲突 |
| 分配 | 服务端统一下发可配置虚拟网段（默认 100.64.0.0/24，OQ-2）内的固定地址（默认 .2）——虚拟 IP 仅作本机监听地址，允许各设备同值、无池上限与回收（v0.4/OQ-13）；CGNAT 段降低与真实内网撞车概率 |
| 实现 | Windows：安装包内置驱动（wintun 或等价方案，技术设计阶段选型）；Linux：/dev/net/tun |
| 生命周期 | 随系统服务启动创建、停止回收；异常自愈（FR-C-202）；卸载清理（FR-C-203） |
| 冲突检测 | 启动时检测本机路由表与虚拟网段冲突，本地 Web 告警（FR-C-204） |

> 注意：本产品的虚拟 IP **不用于节点间三层路由互访**（不做全互通 Overlay），仅作为本地映射监听地址；节点间数据一律走映射规则触发的隧道。因其不参与跨机寻址，**允许各设备使用相同虚拟 IP**（v0.4/OQ-13，原"逐设备分配"表述废止）。

## 2. 端口映射模型（决策 D2 / D3 / D15）

```
访问方设备A                                    服务方设备B（以远程码定位）
虚拟IP 100.64.0.1                              虚拟IP 100.64.0.2
                                               本机服务 :22
应用 ──▶ 100.64.0.1:8080                       开放内网段 192.168.1.0/24（可选）
          │ 映射监听（仅虚拟IP，不碰127.0.0.1）        ▲
          ▼                                        │ B本地发起连接
        加密隧道 ════ P2P直连（打洞）或 中继 ══════════╩═══▶ 127.0.0.1:22
                                                    或 192.168.1.100:445（需白名单）
```

### 映射规则字段表

| 字段 | 说明 | 默认值 |
|---|---|---|
| 名称/备注 | 用户自定义 | — |
| 本地端口 | 监听在**本机虚拟 IP** 上的端口 | 必填 |
| 目标远程码 | 目标设备的地址别名 | 必填 |
| 目标地址 | 对端本机（默认）或对端开放内网段内的 IP | 对端本机 |
| 目标端口 | 目标机器上的服务端口 | 必填 |
| 协议 | TCP 或 UDP，单选（OQ-6 决议：UDP 亦须支持，P1） | TCP |
| 启用/禁用 | 手动启停 | 禁用 |

> 中继回退开关自 v0.4（OQ-10）起为**目标设备级配置**：本机对每个目标设备维护一份 `{relayFallback}`（默认关闭），该设备下全部映射共用；配置入口在设备发现页（FR-C-803），不再属于单条映射的字段。

### 约束

- 同一虚拟 IP 上本地端口不可重复（同协议）；
- 目标地址为内网 IP 时，服务端按对端上报的开放内网段白名单校验（FR-S-802）；
- 映射数据全量同步至服务端存储（FR-S-801），供 Web 后台展示。

## 3. UDP 打洞（NET-3，P0）

1. A、B 分别经服务端内置 STUN（UDP）获取各自公网 IP:端口（FR-S-601）；
2. 双方经控制通道信令互换公网端点（FR-S-502）；
3. 收到信令后**同时**向对方公网端点发送隧道握手包，在各自 NAT 上建立映射；
4. 双向命中后直连建立，隧道在其上承载（加密要求见 [07 §2](07-安全需求.md)）；
5. 适用预期：双方至少一方向为 Full-cone/Restricted-cone NAT 时成功率高。

## 4. TCP 打洞 · 端口预测法（NET-4，P1，决策 D10 / OQ-1 决议）

1. A、B 分别经服务端内置 STUN（**TCP**）获取各自 TCP 公网 IP:端口（FR-S-602）；
2. 双方经信令互换公网端点，并同步发起时刻；
3. 双方按配置的**打洞并发路数 N**（默认 3，范围 1~5，客户端本地 Web 设置 FR-C-808）各自并发 N 条 TCP 连接连向对方，目标端口统一为**对方 STUN 公网端口 + (N−1)**（预判对方 NAT 为新一轮出站连接分配的外部端口）：

| 打洞并发路数 N | 1 | 2 | 3（默认） | 4 | 5 |
|---|---|---|---|---|---|
| 目标端口偏移 | +0（直连 STUN 端口本身） | +1 | +2 | +3 | +4（上限） |

4. 双方 SYN 交叉命中即完成打洞，胜出连接承载加密隧道，其余连接关闭；
5. 适用预期：NAT 对 TCP 同样执行端口转换且外部端口随连接序号**顺序递增**的场景；端口随机分配型 NAT 无法命中，依赖中继回退。

## 5. 映射连接状态机（NET-5）

```
 [禁用] ─启用▶ [打洞中] ─成功▶ [直连] ─隧道断开▶ [打洞中]
                     │                    ▲
                     │失败(超时默认10s可配)  │周期重试60s
                     ▼                    │
              [中继](若该目标设备回退开启) ──┘
                     │
                     ▼ 未开启回退
                 [失败]（本地Web展示原因，可手动重试）
 授权失效（登出/退组/白名单收回/远程码重置）▶ [失效]（停止转发并提示）
```

状态实时展示于客户端本地 Web（FR-C-306）并上报服务端统计（FR-S-503）。通道切换（中继↔直连、重打洞成功）执行"**先排水后切换**"：旧通道在途数据处理完毕后，新通道才承载后续数据，保证数据顺序（NET-75，OQ-7 决议）。

## 6. 中继回退（NET-6，决策 D3）

| 项 | 约定 |
|---|---|
| 触发 | 打洞超时（默认 10s，可配）失败，且该目标设备的回退配置开启（设备层级，D3 v0.4） |
| 路径 | A ↔ 服务端中继 ↔ B；**中继只见密文**（端到端加密不因回退降级，[07 §2](07-安全需求.md)） |
| 承载 | UDP 为主；TCP 承载用于 UDP 被环境封锁场景（FR-S-704，OQ-4） |
| 管理 | 服务端 Web：全局开关、限速、会话列表（FR-S-703） |
| 回切 | 中继状态下每 **60s** 重试直连；切回时执行"先排水后切换"：旧中继通道在途数据处理完毕后，直连通道才承载后续流量，避免数据顺序问题（NET-75，决议 OQ-7） |

## 7. 报文与链路约束（能力级，不锁协议实现）

| 编号 | 约束 |
|---|---|
| NET-71 | 隧道封装须支持 IPv4 载荷的完整透明传输（TCP/UDP 端口映射流量） |
| NET-72 | 应用层心跳/保活：NAT 映射保活间隔须小于常见 NAT 老化时间（默认 ≤25s，可配） |
| NET-73 | 分片与 MTU：隧道内传输的报文须处理 MTU 差异（分段/重组或 MSS 钳制），避免大包黑洞 |
| NET-74 | 打洞信令与数据通道分离：信令走控制通道（服务端），数据不经过信令连接 |
| NET-75 | 通道切换有序性：任何数据通道切换（中继↔直连、重打洞成功）必须先排空旧通道在途数据，再在新通道发送后续数据（OQ-7 决议） |
