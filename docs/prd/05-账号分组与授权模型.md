# 05 · 账号分组与授权模型

> 所属文档集：[README](README.md)　本文是全产品权限与发现规则的唯一权威定义，03/04 文档引用此处。

## 1. 实体关系

```
用户(1) ──拥有──▶ 设备(n)                 设备=运行客户端的一台机器
用户(1) ──拥有──▶ 分组(n)                 分组属于账号（决策 D8）
分组(m) ◀──加入── 设备(n)                 多对多；凭邀请码或默认分组加入
设备(1) ──持有一个── 远程码                服务端签发的地址别名（决策 D7）
设备(1) ──分配一个── 虚拟IP                服务端统一分配
访问设备(1) ──创建── 映射规则(n)           映射归访问方设备所有，目标以远程码引用
服务设备(1) ──声明── 开放内网段(n)         目标侧暴露面控制（决策 D15）
```

关键规则：

- **设备归属账号**：客户端登录某账号后，该设备绑定到该账号（"本账号名下设备"）；登出后绑定保留，能力降级为哑节点（原始需求第 7、8 条）。
- **分组属于账号，可跨账号共享**：分组所有者生成邀请码，其他账号的设备凭码入组（决策 D8）。
- **一台设备可加入多个分组**，可见设备 = 并集。

## 2. 发现规则

| 视角 | 可见范围 |
|---|---|
| 已登录客户端 | ① 本账号名下全部设备（含离线，标注状态）② 已加入各分组内的全部设备（含其他账号共享进组的设备） |
| 哑节点（未登录） | **不可见任何列表**（不查询）；自身对其所属分组的其他成员**可见**（被发现） |
| 列表字段 | 设备名、设备 ID、远程码、在线状态、所属分组、开放内网段（如有）；虚拟 IP 为本机监听地址、各设备同值非身份标识（v0.4/OQ-13） |

## 3. 登录 / 未登录能力矩阵（原始需求第 8 条的完整展开）

| 能力 | 已登录 | 哑节点（未登录） |
|---|:---:|:---:|
| 作为服务方被映射 / 被连接 | ✓ | ✓ |
| 出现在所属分组成员列表（被他人发现） | ✓ | ✓ |
| 接收打洞信令并配合打洞 | ✓ | ✓ |
| 上报心跳 / 自身配置（内网段白名单等被动同步） | ✓ | ✓ |
| 本地 Web 查看本机状态、管理开放内网段 | ✓ | ✓ |
| **主动发起打洞（作为访问方建立映射）** | ✓ | **✗** |
| **查询设备列表 / 分组列表 / 账号数据** | ✓ | **✗** |
| **创建分组 / 凭邀请码加入分组** | ✓ | **✗**（仅首启向导可选默认分组或预置邀请码） |
| **创建 / 启用端口映射** | ✓ | **✗** |

> 服务端是执行者：哑节点发起的上述"✗"类请求一律拒绝（FR-S-803），客户端本地也置灰对应入口。哑节点被禁用账号收录后（FR-S-204），上述 ✓ 项中依赖账号的部分自动失效。

## 4. 映射建立的授权判定链

访问方创建并启用一条映射时，按顺序校验：

```
L1 访问方处于登录状态（哑节点拒绝）
L2 目标设备 ∈ {访问方账号名下设备} ∪ {与访问方设备存在共同分组的目标设备}
L3 目标地址判定（决策 D15）：
   - 目标 = 对端本机（虚拟IP/localhost） → 默认允许
   - 目标 = 对端内网 IP          → 需对端已声明包含该 IP 的开放内网段
L4 服务端执行 L2/L3 校验后才转发打洞信令（FR-S-501）
L5 打洞失败 → 仅当访问方对该目标设备的回退配置开启时建立中继路径（决策 D3，v0.4 设备层级）
```

说明：

- 远程码在 L2 中只是**定位目标的别名**，持码本身不产生任何授权（决策 D7）；
- 授权在服务端执行而非仅客户端自查，防止篡改客户端绕过（威胁模型见 [07 §1](07-安全需求.md)）；
- 任意一层失效（登出、退组、目标重置远程码、对端收回内网段）→ 存量映射进入失效态并停止转发（FR-C-702）。

## 5. 远程码生命周期

| 阶段 | 行为 |
|---|---|
| 签发 | 设备注册成功时服务端生成并下发（格式 OQ-8），全局唯一、便于手工输入 |
| 使用 | 出现在可见设备列表中；创建映射时作为目标引用 |
| 重置 | 设备所有者/管理员触发，**旧码立即失效**；引用旧码的存量映射标记失效并提示重新配置 |
| 失效 | 设备解绑/删除时一并作废 |

## 6. 示例场景（模型走查）

**场景 1 · 哑节点被运维映射（S3）**
机房服务器 B 以哑节点加入默认分组 → 运维机 A 登录 alice 账号并加入默认分组 → A 列表可见 B（同组）→ A 建映射 `A虚拟IP:2222 → B(远程码):22` → L1✓ L2✓（同组）L3✓（对端本机）→ 打洞 → A 上 `ssh -p 2222 root@100.64.0.1` 即达 B 的 sshd。

**场景 2 · 访问对端内网 NAS（S2）**
办公室机器 C 登录 bob 账号，在本地 Web 开放内网段 `192.168.1.0/24` → 家庭 PC A（alice，与 C 同组"office"）建映射 `A虚拟IP:5000 → C(远程码):192.168.1.100:445` → L3 经白名单校验通过 → 访问 NAS SMB。

**场景 3 · 跨账号协作（S5）**
alice 建组 "team"，策略=需审批，生成邀请码给 bob → bob 的设备凭码申请入组 → alice 批准 → 双方组内互见、可互建映射（L2 成立）。

**场景 4 · 远程码泄露**
攻击者拿到 B 的远程码但与 B 无共同分组、非同账号 → L2 不成立 → 服务端拒绝转发信令，无法建立任何映射（决策 D7 的意义）。
