# 01 · 产品概述

> 所属文档集：[README](README.md)　需求编号前缀：无（本文为背景与范围）

## 1. 背景与问题

家庭、办公室、云端主机常处于 NAT 之后，没有公网 IP，导致：

- 想从家里访问办公室电脑的远程桌面 / SSH，或访问办公室内网的 NAS、打印机、开发测试服务，均无法直达；
- 传统内网穿透工具（如 frp）将**所有流量经服务器中转**，带宽、延迟、流量成本都受限于服务器，且服务器成为单点瓶颈与隐私风险点；
- 商业 P2P 组网工具（Tailscale / ZeroTier）依赖厂商控制服务器（或需要付费自建协调服务），数据面策略、设备授权、服务暴露规则均不可完全自主掌控。

## 2. 产品定位

**一句话定位**：一套自部署的 P2P 内网穿透工具——服务端只负责"登记、授权、分组、打洞协调"，客户端之间通过打洞建立加密直连隧道，以端口映射的方式互访服务；打洞失败时可按配置回退到服务端内置中继。

核心特征：

1. **控制面中心化、数据面去中心化**：日常业务流量在客户端之间点对点传输，不消耗服务器带宽；
2. **端口映射模型**：每台客户端拥有独立虚拟 IP，访问方手动建立"本机虚拟IP:端口 → 目标机器:端口"的映射，只有被映射的服务可达（最小暴露面）；
3. **哑节点支持**：客户端可以不登录账号而长期运行——它仍能被同组设备发现、被连接、被映射（适合无人值守的服务器 / NAS），但不能主动发起访问或获取任何业务数据；
4. **完全自主可控**：账号、分组、授权、密钥、日志全部在自己部署的服务端上。

## 3. 目标用户与部署规模（决策 D4）

| 维度 | 设定 |
|---|---|
| 目标用户 | 个人开发者、家庭实验室、小团队（运维/开发小组） |
| 部署方式 | 用户自备一台公网 VPS（或公网可达的内网机器）部署服务端 |
| 规模上限 | 几十~几百台客户端设备、几十个分组，单管理员即可运营 |
| 明确不做 | SaaS 多租户、计费、公众开放注册运营（见第 6 节） |

## 4. 核心使用场景

| # | 场景 | 说明 |
|---|---|---|
| S1 | 远程办公 | 家庭 PC 登录账号后，映射办公室电脑的远程桌面 / SSH 端口，如同拨入办公网络 |
| S2 | 访问对端内网 | 办公室客户端在本地 Web 显式开放内网段（如 192.168.1.0/24）后，家庭 PC 可映射办公室同网段的 NAS / 打印机 |
| S3 | 无人值守设备 | 机房服务器以哑节点方式部署（不登录），运维机与之同组后即可映射其管理端口 |
| S4 | 服务端自身管理 | 服务端机器上部署一个客户端，管理员通过端口映射安全接入服务端 Web 后台（服务端 Web 不对公网监听） |
| S5 | 跨账号协作 | 团队成员各自账号，凭分组邀请码加入同一分组，组内设备互相可建映射 |
| S6 | 恶劣 NAT 兜底 | 双方均为对称型 NAT 导致打洞失败时，开启了中继回退的目标设备，其映射自动经服务端中继（密文转发）保持可用（v0.4：回退开关为设备层级） |

## 5. 竞品对照

| 能力 | frp | Tailscale / ZeroTier | 本产品 |
|---|---|---|---|
| 数据路径 | 全部经服务器中转 | P2P + 中继兜底 | **P2P + 可配置中继兜底** |
| 访问模型 | 端口映射 | 虚拟 IP 全互通 | **虚拟 IP + 手动端口映射（最小暴露面）** |
| 控制面 | 自建 | 厂商托管（自建门槛高） | **自建，单文件部署** |
| 未登录节点 | 不适用 | 不支持 | **支持哑节点（被动可达）** |
| 服务发现 | 无 | 网段内全互通 | 同账号 + 同分组设备可见 |
| 管理界面 | 服务端有 | 厂商控制台 | 服务端 + 客户端各有 Web 页 |
| 目标平台 | Linux/Windows | 全平台 | **Linux + Windows** |

## 6. 范围界定

### 6.1 首版做

- Windows / Linux 客户端（系统服务 + 本地 Web 管理页）
- 服务端（Linux 优先，同代码支持 Windows）
- 虚拟网卡 + 独立虚拟 IP + 手动端口映射（TCP 与 UDP，OQ-6 决议）
- UDP 打洞 + TCP 打洞（端口预测法，决策 D10）
- 服务端内置 STUN（UDP/TCP）与中继（目标设备级回退开关，决策 D3，v0.4）
- 账号、分组（跨账号共享、准入可配置）、远程码、哑节点（D6~D9）
- 双端 Web 管理页（D11）、性能可观测（D12）

### 6.2 首版不做（记录以免范围蔓延）

- 桌面 GUI / 系统托盘程序（D14：仅系统服务 + Web 页）
- IPv6 直连优先、UPnP/NAT-PMP/PCP 自动端口映射（打洞范围仅 D10 两种，见 06 文档）
- SaaS 多租户、多管理员、运营级操作审计、计费（单管理员安全审计日志仍按 NFR-54 交付，v0.3 澄清）
- 移动端（Android/iOS）
- 客户端自动升级（保持手动升级；协议不兼容时仅自动弹出升级引导页，见 FR-C-904）
- 抗 DPI 混淆的具体实现（PRD 仅保留能力扩展点，D5）

## 7. 设计原则

1. **服务器不碰业务流量**：能直连则直连；必须中继时，中继只转发密文（不可解密）。
2. **最小暴露面**：默认只暴露被显式映射的端口；访问对端内网需对端显式开放网段（D15）。
3. **哑节点零业务数据**：未登录客户端从服务端获取的信息被限制在"打洞信令 + 被动状态同步"范围内。
4. **能力优先于实现**：隧道协议、加密协议在 PRD 层面只约定能力（加密、混淆可扩展、密钥可轮换），具体选型在技术设计阶段确定（D5）。
5. **自部署友好**：单二进制、默认配置可跑、Web 页本地化，管理面不强制依赖公网暴露。
