# 02 · 总体架构

> 所属文档集：[README](README.md)

## 1. 架构总览

```
                        ┌─────────────────────────────────────────────┐
                        │              服务端（公网 VPS）               │
                        │                                             │
                        │   控制API/信令 ── STUN(UDP/TCP) ── 中继      │
                        │   （注册/心跳/信令）  （公网端点探测） （密文转发）│
                        │   Web后台（仅本机监听，经映射远程接入）          │
                        └────────┬──────────────┬───────────┬─────────┘
                                 │              │           │
                     控制通道(注册/心跳/信令/配置同步)│      中继兜底(密文)
                                 │      STUN探测 │           │
        ┌────────────────────────┴──────────────┴───────────┴────────────┐
        │                        P2P 加密隧道（打洞直连，决策D10）          │
        │                                                                 │
 ┌──────┴───────────────┐                                   ┌─────────────┴──────┐
 │  客户端A（访问方，登录） │                                   │ 客户端B（服务方，可为哑节点）│
 │  虚拟IP: 100.64.0.1   │ ═══════════ 隧道 ════════════════▶ │  虚拟IP: 100.64.0.2 │
 │                      │                                   │                    │
 │  应用 → 100.64.0.1:8080（虚拟网卡上的映射监听）              │  本机服务 :22       │
 │  本地Web: 127.0.0.1   │      映射规则：A:8080 → B的22端口    │  开放内网段（可选）   │
 │  系统服务             │                                   │  本地Web: 127.0.0.1 │
 └──────────────────────┘                                   └────────────────────┘
```

要点：

- **控制通道**（客户端 ↔ 服务端）：设备注册、心跳、账号登录态、分组与映射数据同步、打洞信令交换；
- **数据通道**（客户端 ↔ 客户端）：承载映射流量的加密隧道，打洞直连优先，按**目标设备级回退配置**回退中继（D3 v0.4）；
- **服务端 Web 后台不对公网监听**：远程管理走"服务端机器上部署客户端 + 端口映射"的路径（决策 D11，见第 3.7 节流程 F7）。

## 3. 关键流程

### 3.1 F1 · 首次启动与注册

```
客户端安装并启动系统服务
  → 检测到未注册 → 自动打开浏览器访问 127.0.0.1 配置页（首启向导）
  → 用户选择：加入默认分组 / 输入邀请码加入指定分组 / 登录(或注册)账号后新建分组
  → 客户端以 MAC 生成的初始识别码向服务端发起注册
  → 服务端签发：设备ID（持久化凭据）+ 远程码 + 虚拟IP + 分组成员资格
  → 客户端创建虚拟网卡并应用虚拟IP，进入在线状态
```

约束：未登录时仅可选择"默认分组"或"凭邀请码入组"，不能新建分组（决策 D8）。

### 3.2 F2 · 设备发现（登录后）

```
客户端登录账号 → 服务端下发可见设备列表：
  ① 该账号名下的全部设备
  ② 该客户端已加入的各分组内的全部设备（含其他账号共享进组的设备）
列表内容：设备名、设备ID、远程码、虚拟IP、在线状态、所属分组
```

### 3.3 F3 · 端口映射建立（访问方发起）

```
用户在客户端A本地Web创建映射：本机虚拟IP:8080 → 目标(远程码):22，协议TCP（目标设备B的回退配置=开，D3 v0.4）
  → A 校验授权：目标 ∈ 本账号设备 ∪ 同分组设备（见 05 §4 授权判定链）
  → A 请求服务端协调打洞 → 服务端校验授权后向 A、B 互换公网端点信令
  → A、B 执行打洞（F4/F5）
  → 打洞成功：建立加密隧道；失败且回退开启：建立中继路径（F6）
  → A 在 100.64.0.1:8080 监听，应用连接后流量经隧道送达 B，由 B 连接其本机(或开放的内网IP):22
```

### 3.4 F4 · UDP 打洞时序

```
A ──STUN(UDP)──▶ 服务端 ──▶ A 得知自己公网 epA
B ──STUN(UDP)──▶ 服务端 ──▶ B 得知自己公网 epB
A ◀──信令互换(epA, epB)──▶ B（经服务端控制通道）
A ──同时向 epB 发包──┐
B ──同时向 epA 发包──┴──▶ 双向包在各自 NAT 上"撞"出映射 → 直连建立 → 承载加密隧道
```

### 3.5 F5 · TCP 打洞时序（端口预测法，决策 D10 / OQ-1 决议）

```
A ──STUN(TCP)──▶ 服务端 ──▶ A 得知自己 TCP 公网端口 portA
B ──STUN(TCP)──▶ 服务端 ──▶ B 得知自己 TCP 公网端口 portB
A ◀──信令互换(公网IP+端口)──▶ B
双方同时：按"打洞并发路数 N"各自并发 N 条 TCP 连接连向对方，
          目标端口 = 对方 STUN 获取的公网端口 + (N−1)
双方 SYN 交叉命中 → TCP 连接建立 → 在其上承载加密隧道
```

| 打洞并发路数 N | 目标端口偏移 | 说明 |
|---|---|---|
| 1 | +0 | 直接连接 STUN 探测到的公网端口本身 |
| 2 | +1 | |
| 3（默认） | +2 | 与 D10 原始约定一致 |
| 4 | +3 | |
| 5 | +4 | 偏移上限 |

> 配置项"打洞并发路数"位于客户端本地 Web 设置（FR-C-808），默认 3、范围 1~5。端口预测假设 NAT 的外部端口随连接序号顺序分配（多数常见 NAT 行为）；端口随机分配型 NAT 无法命中，依赖中继回退。

### 3.6 F6 · 中继回退

```
打洞超时（默认 10s，可配置）判定失败
  → 若该目标设备的回退配置开启（决策 D3，v0.4 设备层级）：A、B 分别与服务端中继建立承载连接
  → 服务端中继仅转发密文（不可解密，见 07 §2）
  → 映射状态标记为"中继"，本地Web可见
  → 后台每 60s 周期性重试直连，成功则"先排水后切换"切回直连路径（OQ-7 决议）
```

### 3.7 F7 · 服务端 Web 远程接入（决策 D11）

```
服务端机器上部署一个客户端（可为哑节点，加入默认分组或管理员指定分组）
管理员自己的客户端（已登录、与该设备同组）建立映射：
  本机虚拟IP:9000 → 服务端设备(远程码):服务端Web端口
管理员浏览器打开 http://虚拟IP:9000 → 流量经加密隧道 → 服务端Web
```

说明：服务端 Web 仅监听本机回环/本机地址，不对公网暴露；首次部署的初始化（首个管理员账号产生，OQ-3）依赖控制端口的注册 API，不依赖 Web 可达。

## 4. 端口与地址规划（默认值均可配置）

| 用途 | 协议 | 默认端口/网段 | 说明 |
|---|---|---|---|
| 服务端 控制 API/信令 | TCP | 7000 | 注册、心跳、登录、配置同步、打洞信令 |
| 服务端 STUN | UDP | 3478 | UDP Binding 探测 |
| 服务端 STUN | TCP | 3478 | TCP Binding 探测（端口预测依据） |
| 服务端 中继 | UDP/TCP | 7010 起（可配范围） | 密文转发；TCP 承载用于 UDP 被封场景（OQ-4） |
| 服务端 Web 后台 | HTTP（仅本机） | 7500 | 经 F7 流程远程接入 |
| 客户端 本地 Web | HTTP（仅 127.0.0.1） | 7100 | 首启自动打开 |
| 虚拟网段 | — | 100.64.0.0/24（可配，OQ-2 决议） | 服务端统一下发网段内固定地址（默认 .2，OQ-13：虚拟 IP 仅本机监听用途、允许各设备同值）；采用 CGNAT 段降低与企业内网冲突概率 |

## 5. 技术约束（决策 D13）

| 项 | 约束 |
|---|---|
| 运行时 | .NET 10（LTS，支持至 2028-11-14）。注：.NET 8 / .NET 9 均于 2026-11-10 停止支持，不得作为目标框架 |
| 服务端平台 | Linux 优先（VPS 部署），同代码支持 Windows |
| 客户端平台 | Windows 10 1809+ / Windows 11 / Windows Server 2019+；主流 Linux 发行版（x64/arm64，内核支持 TUN） |
| 虚拟网卡 | Windows：随安装包分发驱动（wintun 或等价方案，实现阶段选型）；Linux：/dev/net/tun |
| 交付形态 | 单文件自包含发布；Windows 安装包（含驱动）；Linux 二进制 + deb/rpm；服务端提供 Docker 镜像 |
| Web 托管 | 内置 Web 服务器（如 Kestrel），无外部依赖 |
| 隧道协议 | 不锁定实现，仅约定能力（端到端加密/混淆可扩展/密钥可轮换，决策 D5），详见 [07](07-安全需求.md) |
