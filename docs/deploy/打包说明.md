# 打包说明

> 适用版本：1.0.0　依据：设计 08 §1（版本注入）/§2⑤/§3、NFR-31~33
> **分发口径：Windows = Setup exe／Linux = tar.gz（服务端 + 客户端各一枚）**；deb/rpm/Docker/portable 为可选扩展形态，见各部署手册进阶节。
> 打包入口唯一：仓库根 `sh build/package.sh <目标>`。构建机为 Windows（Git Bash）；产物对目标平台自包含，目标机免装 .NET。

## 0. 打包链路（一段话）

前端 `pnpm build`（产物直写宿主项目 wwwroot）→ `dotnet publish` 单文件自包含（单 exe + wwwroot）→ `out/` 产物目录（脚本自动校验：可执行体 + wwwroot/index.html 在位）→ Linux 目标追加 `tar.gz` 归档／win-setup 目标经 Inno Setup 编译成单 exe。

```text
sh build/package.sh <目标>
  ├─ pnpm -C web --filter <前端包> build        # client-app 或 server-app
  ├─ dotnet publish src/<P2P.Client|P2P.Server> -r <win-x64|linux-x64> → out/<目录>/
  ├─ [Linux] tar -czf out/P2PSocket-<目标>-v<版本>.tar.gz -C out/<目录> .
  └─ [win-setup] ISCC 编译 deploy/client/win/P2PSocket-Client.iss → out/P2PSocket-Client-Setup-<版本>-x64.exe
```

## 1. 环境依赖

| 依赖 | 用途 | 安装/准备 |
|---|---|---|
| dotnet SDK 10 | publish | — |
| node ≥20 + pnpm | 前端构建 | `corepack enable pnpm` |
| Git | 版本哈希注入 | — |
| Inno Setup 6（仅 win-setup） | 编译安装包 | `winget install JRSoftware.InnoSetup`；未装则**跳过安装包并如实标注**（不报错） |
| Wintun.dll（仅 win-setup / client-win） | Windows TUN 驱动库 | 官方 [wintun.net](https://www.wintun.net) 0.14.1 amd64，不入库；置于 `out/wintun/Wintun.dll` 后脚本自动拷入，缺失仅警告——**分发前须手工放置** |

## 2. 核心命令（三件分发件）

每条命令只收一个目标；版本号以 `src/Directory.Build.props` 的 `<Version>` 为准（当前 1.0.0，下例以此为例）。**打包前先 `git commit`**（原因见 §3）。

### 2.1 Windows 安装包（win-setup）

```bash
cd /d/AICode/AI_P2P_Project                                     # 仓库根（Git Bash）
git status --short                                              # ① 应无未提交改动——先提交再打包
sh build/package.sh win-setup                                   # ② 前端构建 → publish → ISCC 编译
sha256sum -c out/P2PSocket-Client-Setup-1.0.0-x64.exe.sha256    # ③ 清单核验
# 产物：out/P2PSocket-Client-Setup-1.0.0-x64.exe（~36MB）→ [Windows 客户端部署手册](Windows客户端部署手册.md)
```

> 命名口径：分发件统一 `P2PSocket-*` 前缀、安装器显示名「P2PSocket 客户端」；但**服务名 `P2PClient` 与数据目录 `%ProgramData%\P2PClient` 刻意不改**——已装机的覆盖升级与数据保留依赖二者，勿顺手「纠正」。

### 2.2 Linux 服务端（server）

```bash
git status --short
sh build/package.sh server
sha256sum -c out/P2PSocket-server-v1.0.0.tar.gz.sha256
# 产物：out/P2PSocket-server-v1.0.0.tar.gz → [服务端部署手册](服务端部署手册.md)
```

### 2.3 Linux 客户端（client-linux）

```bash
git status --short
sh build/package.sh client-linux
sha256sum -c out/P2PSocket-client-linux-v1.0.0.tar.gz.sha256
# 产物：out/P2PSocket-client-linux-v1.0.0.tar.gz → [Linux 客户端部署手册](Linux客户端部署手册.md)
```

每个分发件随打包自动产出同名 `.sha256` 清单，并汇总 `out/SHA256SUMS`——目标机 `sha256sum -c <清单>` 直接核验（Windows 目标机用 `Get-FileHash` 比对）。

## 3. 版本号与打包纪律

| 来源 | 去向 |
|---|---|
| `src/Directory.Build.props` 的 `<Version>`（当前 1.0.0，手动递进——单一事实源） | 归档/Setup exe 文件名、运行时 `/api/system/state` 的 `version` 字段 |
| `git rev-parse --short HEAD` + 构建 UTC 时间 | `/api/system/state` 的 `commit` 字段、日志启动行 |

**纪律：打包前先 `git commit`**——版本注入取 HEAD 哈希，工作区未提交的改动不会体现在版本号里，线上排障会对不上 commit。升级流程固定为「先提交、再自 HEAD 重打包」。git 不可用（源码包构建）容错为 `unknown`，不阻断构建。

## 4. 可选目标（按需查阅）

| 目标 | 命令 | 用途 |
|---|---|---|
| client-win | `sh build/package.sh client-win` | portable 形态产物（目录，无归档）——已装服务机的覆盖升级 / 手工部署，见 [Windows 客户端部署手册](Windows客户端部署手册.md) §4.2 |
| all（缺省） | `sh build/package.sh` | client-win + client-linux + server 三连（不含 win-setup） |

- 分发件哈希可录入服务端管理页「升级-产物SHA-256」（server_config `update_artifact_sha256`，JSON 键 windows-setup/linux-tar/server-tar），客户端升级页按平台展示与核验；
- deb/rpm：见 [Linux 客户端部署手册](Linux客户端部署手册.md) §5；Docker：见 [服务端部署手册](服务端部署手册.md) §5.2。

## 5. 产物内容与已知坑

顶层内容（tar 归档为 `./` 散开，`tar -xzf xxx.tar.gz -C <目标目录>` 直落）：

| 件 | server tar | client-linux tar | client-win 目录 |
|---|---|---|---|
| 可执行体 | p2p-server | p2p-client | p2p-client.exe |
| wwwroot/（Web 静态资源） | ✓ | ✓ | ✓ |
| pdb（3 枚）+ staticwebassets.endpoints.json | ✓ | ✓ | ✓（另 web.config） |
| libe_sqlite3.so | ✓ | — | — |
| **appsettings.json（默认值）** | **✓（见坑 1）** | — | —（客户端配置在 ProgramData//etc，不随包） |
| Wintun.dll | — | — | ✓（out/wintun/ 在位时） |

**踩坑四条（历次实弹）：**

1. **server tar 含默认 appsettings.json**——线上解包会覆盖运行配置（webBind、心跳超时等）。远端升级必须「备份 appsettings.json → 解压 → 回放」三步，或上传时排除该文件。
2. **Windows 构建的 tar 丢执行位**——Linux 解包后须 `chmod +x`（或 `install -m 755`），否则 systemd 起 203/EXEC。
3. **exe 与 wwwroot 必须同目录**——SPA 静态托管按 AppContext.BaseDirectory 解析。
4. **版本验证走 `/api/system/state` 的 version/commit 字段**——`p2p-client --version` 不是有效参数，会真启动第二实例（端口冲突崩退，不影响已装服务但别用）；单文件首启有 ~12s 自解压期，期间 `systemctl is-active` 显示 activating 属正常，等再查。
