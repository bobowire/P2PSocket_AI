# 服务端部署手册

> 适用版本：1.0.0　依据：NFR-31/34、设计 08 §3.3/§5.1/§7、D11
> 阅读方式：**§0–§4 为核心流程**（裸机 Linux + systemd，照做即可上线）；**§5 为进阶配置、§6 为常见问题**——Docker、数据加密、配置参考等非默认路径都在那里，遇到对应需求再查阅。
> 早期实机部署实录（M1-37 验收记录）见 [docs/部署文档/公网服务端部署.md](../部署文档/公网服务端部署.md)，最新口径以本手册为准。

## 0. 部署总览

| 步骤 | 做什么 | 在哪做 |
|---|---|---|
| ① | 放行端口（云安全组） | 云控制台 |
| ② | 打包取得服务端 tar.gz | 构建机 |
| ③ | 上传、创建运行账户、装 systemd 服务并启动 | 构建机 + 服务器 |
| ④ | 首启验证 | 服务器 |
| ⑤ | 初始化：改管理密码、设 public_addr | 管理后台 |

前置条件：

- 一台公网 VPS：Linux x64（Debian 12 验证，glibc 2.31+），免装 .NET/SQLite；2C/2GB 实测承载 500 设备（默认上限）稳态 CPU<1%，中继吞吐受带宽与两端 CPU 约束；须运行 NTP（协议含时钟偏差校验，云镜像默认已配）；
- 构建机能 SSH 免密登录该服务器（无密钥先 `ssh-keygen -t ed25519`，再 `ssh-copy-id root@<IP>`，或经云控制台把公钥手工加进服务器 `/root/.ssh/authorized_keys`）；
- 构建机已装好打包依赖（见 [打包说明](打包说明.md) §1）。

## 1. 放行端口（云控制台安全组）

| 端口 | 协议 | 用途 | 放行 |
|---|---|---|---|
| 7000 | TCP | 控制面（注册/登录/信令/映射） | **必须** |
| 3478 | UDP + TCP | STUN 打洞探测 / STUN-TCP 桥接 | **必须（两种协议都放）** |
| 7010-7020 | TCP + UDP | 中继数据面（打洞失败时的回退承载） | **必须（两种协议都放）** |
| 7500 | TCP | Web 管理后台 | **不放行**（仅本机回环，见 §3.3） |

UDP 3478 的连通性**不能用「裸 STUN 探测无响应」判断**：服务端默认开启设备鉴权，未带鉴权的探测包会被静默丢弃——「无响应 ≠ 不通」。要验证安全组是否放行，在服务器上抓包看入方向：

```bash
tcpdump -ni any udp port 3478
# 保持运行，从本机向 <IP>:3478 随意发几个 UDP 包；看到 In 方向的包即放行成功
```

## 2. 打包与安装

以下 `<IP>` 均指服务器公网 IP。

### 步骤 1：打包（构建机）

```bash
sh build/package.sh server
# 产物：out/P2PSocket-server-v1.0.0.tar.gz（版本号随 src/Directory.Build.props 变化）
```

版本号与构建提交在打包时统一注入，管理后台左上角与 `/api/system/state` 可查（升级后核对版本用）。

完整打包流程见 [打包说明](打包说明.md)。

### 步骤 2：上传（构建机执行，直解压到服务器）

```bash
tar -C out/server -czf - --exclude='*.pdb' p2p-server libe_sqlite3.so appsettings.json \
    staticwebassets.endpoints.json wwwroot \
  | ssh root@<IP> "mkdir -p /opt/p2p/server && tar -C /opt/p2p/server -xzf -"
```

tar 管道直解压，不在本机留压缩包；`data/`、`logs/` 不在包内，后续升级不会碰到数据库与日志。

### 步骤 3：创建运行账户与数据目录（服务器）

```bash
ssh root@<IP> '
useradd -r -s /usr/sbin/nologin p2p
mkdir -p /opt/p2p/server/data /opt/p2p/server/logs
chown -R p2p:p2p /opt/p2p/server/data /opt/p2p/server/logs
chmod 750 /opt/p2p/server/data /opt/p2p/server/logs
chmod +x /opt/p2p/server/p2p-server'
```

服务以专用非特权账户 `p2p` 运行（最小权限）；部署目录其余文件保持 root 属主只读——p2p 用户仅需读+执行，连自身二进制都不可篡改。

### 步骤 4：安装 systemd 服务并启动

```bash
scp deploy/server/p2p-server.service root@<IP>:/etc/systemd/system/p2p-server.service
ssh root@<IP> 'systemctl daemon-reload && systemctl enable --now p2p-server'
```

仓库 unit 文件已配好：非特权运行 + 沙箱（全文件系统只读，仅 data/logs 白名单可写）、`WorkingDirectory=/opt/p2p/server`（数据库/日志均为相对路径，**勿改**）、开机自启、崩溃 5s 自动拉起。

### 步骤 5：首启验证

**单文件首启需等约 12 秒**（自解包 + 数据库迁移），期间 `systemctl status` 短暂显示 `activating` 属正常。稍候逐项核对：

```bash
ssh root@<IP> 'systemctl status p2p-server --no-pager | head -5'
# 期望：active (running)

ssh root@<IP> 'ss -lntup | grep p2p-server'
# 期望：0.0.0.0:7000(tcp)、0.0.0.0:3478(udp+tcp)、7010-7020、127.0.0.1:7500

ssh root@<IP> 'journalctl -u p2p-server -n 10 --no-pager'
# 期望日志依次出现：「数据库就绪」「控制面监听 …」「STUN-R 监听 …」「服务端启动完成」

ssh root@<IP> 'ls /opt/p2p/server/data /opt/p2p/server/logs'
# 期望：p2p.db(+wal/shm)、app-<日期>.log
```

## 3. 初始化配置（首次上线必做）

### 3.1 登录管理后台，立即改密

首启自动建库并创建内置管理员 **admin/admin**。管理后台只监听服务器回环，先建 SSH 隧道再访问：

```bash
ssh -L 7500:127.0.0.1:7500 root@<IP>
# 保持此窗口，本机浏览器打开 http://127.0.0.1:7500
```

用 admin/admin 登录，**按提示立即修改密码**。

### 3.2 设置 public_addr（必配）

云 VPS 网卡通常只见内网地址，若不设置，中继授权会把**内网端点**通告给客户端导致不可达。在管理后台「系统配置」页把 `public_addr` 设为**服务器公网 IP**，保存。

### 3.3 管理后台的日常进入方式

管理后台绑定 `127.0.0.1:7500`，不对公网暴露。日常两种进入方式：

1. **SSH 隧道**（运维兜底）：同 §3.1 的 `ssh -L 7500:127.0.0.1:7500 root@<IP>`；
2. **经客户端映射**（正式路径）：服务器本机跑一个 p2p-client（见 [Linux 客户端部署手册](Linux客户端部署手册.md)），在任一台客户端上建映射「本地端口 → 服务器设备远程码:self:7500」，经隧道访问。

**不要**把 `webBind` 改成 `0.0.0.0` 并放行 7500——这会把管理面直接暴露到公网。

## 4. 日常运维

### 4.1 常用命令（服务器上执行）

```bash
systemctl status p2p-server                        # 状态
systemctl restart p2p-server                       # 重启
journalctl -u p2p-server -f                        # systemd 侧日志
tail -f /opt/p2p/server/logs/app-$(date +%Y%m%d).log   # 应用日志
cd /opt/p2p/server && ./p2p-server --reset-admin   # admin 密码重置（重置后尽快改密）
```

### 4.2 升级

```bash
# ① 构建机：先 git commit 再重新打包（见打包说明 §3），上传覆盖（不含 data/logs，数据库与日志天然保留）
tar -C out/server -czf - --exclude='*.pdb' p2p-server libe_sqlite3.so appsettings.json \
    staticwebassets.endpoints.json wwwroot \
  | ssh root@<IP> "tar -C /opt/p2p/server -xzf -"

# ② 服务器：先备份旧二进制（回滚件），再重启
ssh root@<IP> 'cp /opt/p2p/server/p2p-server /opt/p2p/server/p2p-server.bak-$(date +%Y%m%d) \
  && systemctl restart p2p-server'

# ③ 验证（留出 ~12s 首启自解包时间再判定）
ssh root@<IP> 'sleep 15 && systemctl is-active p2p-server && journalctl -u p2p-server -n 5 --no-pager'
```

注意：

- 数据库 schema 迁移自动前滚；**schema 只进不退，不支持降版本回滚**——降级前先停用新版本用过的功能面；
- 上传会覆盖 `appsettings.json`——若线上手工改过该文件，①中 tar 命令的文件列表里去掉 `appsettings.json`；
- systemd unit 不随升级覆盖；unit 本身需要变更时，按 §5.4 的方式替换。

### 4.3 回滚

```bash
ssh root@<IP> 'cp /opt/p2p/server/p2p-server.bak-<日期> /opt/p2p/server/p2p-server \
  && systemctl restart p2p-server'
```

### 4.4 数据备份

停服务后打包 `/opt/p2p/server/data/`（SQLite WAL 安全点）。若启用了静态数据加密（§5.3），**备份必须连同 masterKey**——丢钥=旧库凭据不可解，全部设备须解绑后重注册。

## 5. 进阶配置（按需查阅）

### 5.1 配置参考

**appsettings.json（进程级：端口/路径，改动后重启生效）：**

| 键 | 默认 | 说明 |
|---|---|---|
| `listen.control` | 7000 | 控制面 TCP |
| `listen.stunUdp` / `listen.stunTcp` | 3478 / 3478 | STUN 双协议（客户端按控制地址派生，勿改） |
| `listen.relayPorts` | [7010, 7020] | 中继数据面端口段（TCP+UDP） |
| `listen.web` / `listen.webBind` | 7500 / **127.0.0.1** | 管理后台端口/绑定（保持回环，勿改 0.0.0.0） |
| `database.path` | data/p2p.db | 相对 WorkingDirectory |
| `logging.retentionDays` | 14 | 滚动日志保留 |

**业务级开关**在管理后台「系统配置」页改（库键 server_config），部分需重启生效：`public_addr`（§3.2）、`relay_enabled`/`relay_rate_limit`、`stun_auth`/`stun_alt_addr`/`stun_rate_*`、`update_*`（升级引导）、`default_join_policy`、`registration_open`、`max_devices`、`virtual_subnet`、`log_level` 等。

分工口径：**端口/路径在文件，业务开关在库**。

### 5.2 Docker 形态

适合容器化环境；生产裸机部署仍以 §2 为准。完整说明见 [deploy/server/docker/README.md](../../deploy/server/docker/README.md)，要点：

```bash
sh build/package.sh server
docker build -f deploy/server/docker/Dockerfile -t p2p-server:1.0.0 out/server
cd deploy/server/docker && docker compose up -d     # ./data 卷=库+日志；升级=换 tag 再 up -d
```

- 镜像以非 root 用户（uid 1000）运行——`./data` 卷属主须对齐：`chown -R 1000:1000 ./data`（root 属主旧卷直接换镜像=库打不开起不来）；环境裁剪 cap 时须 `--cap-add=NET_BIND_SERVICE`（3478 低口绑定）；
- compose 端口映射 `127.0.0.1:7500:7500` 的回环前缀是管理面不暴露公网的保险，**禁止改成裸 `7500:7500`**；
- `public_addr` 仍是库键，须在管理后台改（容器环境变量不覆盖业务键）。

### 5.3 静态数据加密（可选）

对落库的设备凭据启用 AES-256-GCM 加密。默认不启用（明文存储 + 启动 ERROR 日志 + 管理后台安全页警示横幅，不阻断启动）：

```bash
# ① 生成 64 位 hex 主密钥
openssl rand -hex 32

# ② 写入 /opt/p2p/server/appsettings.json（或环境变量 P2P_MASTER_KEY，优先级更高）：
#    "security": { "masterKey": "<64hex>", "masterKeyPrev": "" }

# ③ 重启——自动迁移存量明文（日志「静态数据加密迁移完成：加密/重加密 N 行」）
systemctl restart p2p-server
```

运维要点：

- **备份必须连同 masterKey**（见 §4.4）；钥在 appsettings.json 则备份该文件即含钥，钥在环境变量/systemd 单元则一并备份；
- **轮换**：新钥填 `masterKey`、旧钥移入 `masterKeyPrev`，重启（启动时旧密文自动重加密为新钥）；日志确认后清空 `masterKeyPrev`；
- 密钥置于 systemd 单元时，推荐放 drop-in 目录 `/etc/systemd/system/p2p-server.service.d/`——**不受 unit 文件替换影响**（见 §5.4）；
- 库文件权限启动自动核对为 0600，无需手工设置。

### 5.4 systemd unit 变更 / 存量 root 部署迁移

**仅适用于 2026-10-23 之前以 root 运行的存量部署**（新装走 §2 已是最小权限）。迁移四步，停机约 1 分钟（客户端自动退避重连，无需用户干预）：

```bash
# ① 停服 + 备份（回滚件：数据目录 + 旧 unit）
ssh root@<IP> 'systemctl stop p2p-server \
  && cp -a /opt/p2p/server/data /root/p2p-data-bak-$(date +%m%d) \
  && cp /etc/systemd/system/p2p-server.service /root/p2p-server.service.bak-$(date +%m%d)'

# ② 创建专用账户 + 移交数据目录属主
ssh root@<IP> 'useradd -r -s /usr/sbin/nologin p2p \
  && chown -R p2p:p2p /opt/p2p/server/data /opt/p2p/server/logs \
  && chmod 750 /opt/p2p/server/data /opt/p2p/server/logs'

# ③ 替换 unit（仓库 deploy/server/p2p-server.service）+ 起服
scp deploy/server/p2p-server.service root@<IP>:/etc/systemd/system/p2p-server.service
ssh root@<IP> 'systemctl daemon-reload && systemctl start p2p-server'

# ④ 核对：运行身份 / 监听 / 沙箱
ssh root@<IP> 'ps -o user= -C p2p-server | sort -u      # 期望 p2p
  ss -lntup | grep p2p-server                           # 期望端口同 §2 步骤 5
  journalctl -u p2p-server --since "-2 min" --no-pager | grep -iE "EACCES|denied|只读|启动完成"'
```

- 迁移后功能验证：既有客户端断线自动重连、新设备注册、打洞与中继回退、Web 后台（SSH 隧道）各过一遍；
- **回退**（回 root 形态，库内容无差别）：

```bash
ssh root@<IP> 'cp /root/p2p-server.service.bak-* /etc/systemd/system/p2p-server.service \
  && systemctl daemon-reload \
  && chown -R root:root /opt/p2p/server/data /opt/p2p/server/logs \
  && systemctl start p2p-server'
```

## 6. 常见问题

| 现象 | 处置 |
|---|---|
| UDP 3478 裸探测无响应 | 多数情况非故障：`stun_auth` 默认开启，未带设备鉴权的探测被静默丢弃。验证放行用服务器 `tcpdump -ni any udp port 3478` 抓包（§1.1） |
| 客户端中继可达性异常 / 中继端点连不上 | 检查「系统配置」`public_addr` 是否已设为公网 IP（§3.2）——缺省时中继把内网端点通告给客户端 |
| `systemctl` 长时间 `activating` | 单文件首启自解包+迁移约 12s，稍候再判；仍失败看 `journalctl -u p2p-server` 具体报错 |
| 日志报 `EACCES` / `Read-only file system` | 沙箱白名单被破坏：data/logs 目录属主须为 p2p、unit 勿手工改动（§2 步骤 3-4） |
| 7500 外网打不开 | 预期行为：管理后台仅回环监听，走 SSH 隧道或客户端映射（§3.3） |
| 升级后起不来 | 看是否覆盖了线上手工改过的 appsettings.json、是否降了版本（schema 只进不退，§4.2） |
