## 1. 验收中发现并修复的两个缺陷（修复后方为通过态）

### 缺陷 1：清单合并双 LAUNCHER（双图标+死条目启动崩溃）

- **现象**：桌面出现两个 P2P Socket 图标；点其一 `ClassNotFoundException: com.p2psocket.client.MainActivity` 崩溃（logcat 实证）。
- **根因**：`Properties/AndroidManifest.xml` 以相对名 `.MainActivity` 声明组件（合并后=`com.p2psocket.client.*`），而 C# 特性未设 `Name=`，真实 Java 包装类生成于 `crc64097a4ccc0aefd013.*`——清单合并按字符串精确名匹配，两套条目并存。
- **修复**：三特性（Activity/Service/BroadcastReceiver）补 `Name="com.p2psocket.client.*"`，手写清单同步改全名对齐（`MainActivity.cs`/`P2pForegroundService.cs`/`BootReceiver.cs`/`Properties/AndroidManifest.xml`）。
- **验证**：重建重装后 LAUNCHER 解析单条目；原崩溃路径 `am start -n com.p2psocket.client/com.p2psocket.client.MainActivity` 正常启动。

### 缺陷 2：Android ECDH ImportParameters 平台不兼容（运行时启动崩溃）

- **现象**：`壳运行时启动失败：CryptographicException at ECAndroid.ImportParameters`（`EcKeyPair.FromPrivateKey → ClientRuntime.AttachPuncher`）；注册后路径同样报错（打洞器未接线，隧道能力整体缺失）。
- **根因**：`FromPrivateKey` 仅传 `D`（私钥标量）不传 `Q`（公钥点）——Windows CNG 支持仅 D 自动推导 Q，Android 的 BouncyCastle 系实现要求 D/Q 成对，缺失即抛。
- **修复**：新增 `src/P2P.Core/Crypto/P256.cs`（P-256 托管标量乘，仿射双加算 Q=d×G），`FromPrivateKey` 传全参数；单测 4 例新增（NIST/SEC 2 标准向量锁死数学正确性+双侧导入 ECDH 一致+越界拒绝），`P2P.Core.Tests` EcKeyPair 7/7 绿。
- **连带修复**：Android 工程 `BuildP2PClient` 自举 Inputs 补 `P2P.Core`/`P2P.Nic` 源码（原仅盯 P2P.Client 源码，Core 改动会被增量检查漏掉致陈旧 dll 进 APK）。
- **验证**：重建重装后启动日志 `打洞器已接线（STUN=139.155.70.54:3478）`，无 CryptographicException。
