# 01 · 总体架构设计

> 所属文档集：[README](README.md)

## 1. 系统架构（部署视图）

```
                         公网 VPS
                ┌──────────────────────────────┐
                │  P2P.Server（单进程）          │
                │  ├─ ControlServer  :7000/TCP   │  私有协议(MessagePack over 长连接)
                │  ├─ StunService    :3478/UDP+TCP│ Binding 探测(带设备认证)
                │  ├─ RelayService   :7010+/UDP+TCP│ 密文中继
                │  ├─ ServerWebApi   :7500(仅本机)│─┐
                │  └─ SQLite 数据文件  p2p.db      │ │ Cookie 会话
                └──────────┬───────────────────┘  │ 管理员浏览器(经映射接入,F7)
      控制通道/STUN/中继    │                       │
─────公网/内网边界─────────┼────────────────────────┼──────────────
                           │                        │
 ┌─────────────────────────┴──────────┐   ┌─────────┴──────────────┐
 │  P2P.Client（A，访问方）             │   │  P2P.Client（B，服务方）  │
 │  ├─ NicManager(Wintun/TUN 虚拟IP)    │   │  同左（可为哑节点）        │
 │  ├─ MappingEngine(映射监听/流对接)    │   │  目标服务 :22 等         │
 │  ├─ Puncher(UDP/TCP 打洞)           │   │  开放内网段(可选)         │
 │  ├─ TunnelHost(加密隧道/复用)        │   │                        │
 │  ├─ ControlClient ⇢ Server:7000     │   │                        │
 │  └─ LocalWebApi :7100(仅127.0.0.1)  │   │                        │
 │      └─ 内嵌 Vue SPA                 │   │                        │
 └───────────────┬────────────────────┘   └────────────────────────┘
                 │      P2P 加密隧道（UDP/TCP 直连，或经中继）
                 └──────────────────────────────────▶
```

要点（对应 PRD 02）：

- **服务端无公网 HTTP**（TD-08）：对外暴露面 = 7000/TCP + 3478/UDP+TCP + 7010/UDP+TCP，全部为私有二进制协议；
- **客户端对本地应用呈现**：虚拟 IP 上的监听端口（如 `http://100.64.0.1:8080`），数据经隧道直达对端；
- 业务流量路径：`应用 → 虚拟IP:本地端口 → 映射引擎 → 加密隧道 → 对端映射引擎 → 对端本机/开放内网段:目标端口`。

## 2. 解决方案结构（单仓库）

```
AI-P2P.sln
├─ src/
│  ├─ P2P.Core/                 # 共享类库（无宿主依赖）
│  │   ├─ Protocol/             #   控制协议消息定义 + MessagePack schema
│  │   ├─ Tunnel/               #   隧道帧编解码、channel 复用模型
│  │   ├─ Stun/                 #   STUN 报文编解码（RFC5389 子集，客户端/服务端共用）
│  │   ├─ Crypto/               #   ECDH/HKDF/AesGcm/HMAC 封装、密钥体系
│  │   └─ Utils/                #   Pipelines 分帧、重试、日志约定
│  ├─ P2P.Nic/                  # 虚拟网卡封装
│  │   ├─ Windows/              #   Wintun P/Invoke + IP Helper 配址
│  │   └─ Linux/                #   TUN ioctl + netlink 配址
│  ├─ P2P.Server/               # 服务端宿主（Worker 服务 + Kestrel）
│  │   ├─ Services/             #   ControlServer / StunService / RelayService
│  │   ├─ Web/                  #   ServerWebApi（Minimal API，仅本机）
│  │   ├─ Data/                 #   EF Core（SQLite）仓储与迁移
│  │   └─ wwwroot/              #   构建时嵌入 server-app 产物
│  └─ P2P.Client/               # 客户端宿主（Worker 服务 + Kestrel）
│      ├─ Nic/ Mapping/ Punch/ Tunnel/   # 模块宿主（见 05）
│      ├─ Web/                  #   LocalWebApi（Minimal API，仅 127.0.0.1）
│      └─ wwwroot/              #   构建时嵌入 client-app 产物
├─ web/
│  ├─ ui-shared/                # 共享前端库：布局、API client、WS client、图表、类型
│  ├─ client-app/               # 客户端本地 Web（Vue 3）
│  └─ server-app/               # 服务端 Web 后台（Vue 3）
├─ tests/
│  ├─ P2P.Core.Tests/           # 协议编解码、加密、防重放单测
│  ├─ P2P.Server.Tests/         # 控制服务、授权判定、仓储测试
│  ├─ P2P.Client.Tests/         # 映射引擎、状态机、哑节点测试
│  └─ P2P.IntegrationTests/     # 三进程互通、NAT 模拟打洞（见 09）
├─ build/                       # 打包脚本（Inno Setup / deb / rpm / Docker）
└─ docs/
```

规则：

- `P2P.Core` 不引用任何宿主项目；`P2P.Server`/`P2P.Client` 引用 `Core`；`P2P.Nic` 仅被 `Client` 引用（服务端不装网卡）；
- 协议消息类型集中在 `Core/Protocol/messages.md` 对应的 C# record（单一事实来源，前后端 TS 类型由构建脚本导出，见 06 §5）。

## 3. 进程模型

### 3.1 服务端（P2P.Server）

以 .NET Generic Host 承载的**单进程多服务**：

| 服务 | 实现 | 并发模型 |
|---|---|---|
| ControlServer | `IHostedService`，TCP 7000 监听 | 每连接一个 `ControlSession`（Pipelines 读写循环 + `Channel<Message>` 收发队列）；设备连接注册表 `ConcurrentDictionary<deviceId, ControlSession>` |
| StunService | UDP 3478 Socket + TCP 3478 监听 | 无状态处理循环（UDP 单socket收发；TCP 短事务连接） |
| RelayService | UDP 7010 起 + TCP 监听 | 会话表 `ConcurrentDictionary<relaySessionId, RelaySession>`；每会话双端地址学习与转发（见 05 §6） |
| ServerWebApi | Kestrel，绑定 `127.0.0.1:7500` | ASP.NET Core 常规模型 |
| 后台任务 | 设备离线判定（心跳超时 30s）、统计落库定时器、密钥清理 | `PeriodicTimer` |

### 3.2 客户端（P2P.Client）

同样为 Generic Host（Windows Service / systemd 承载，FR-C-901）：

| 服务 | 实现 | 说明 |
|---|---|---|
| ControlClient | 到服务端 7000 的 TCP 长连接，断线指数退避重连（FR-C-604） | 登录态/信令/配置同步的唯一通道 |
| NicManager | 创建/恢复虚拟网卡并应用虚拟 IP（FR-C-201/202） | 启动即执行；失败进入降级模式（本地 Web 告警） |
| MappingEngine | 每条启用映射一个 `TcpListener`（绑虚拟 IP） | accept → channel → 隧道（见 05 §3） |
| Puncher | 按需执行 UDP/TCP 打洞（并发路数 N 可配） | 打洞结果驱动映射状态机 |
| TunnelHost | 维护设备对隧道集合：直连 + 中继备用路径 | 会话密钥管理与轮换（SEC-14） |
| LocalWebApi | Kestrel，绑定 `127.0.0.1:7100` | 内嵌 SPA；无鉴权（TD-12） |
| 首启向导探测 | 未注册状态时尝试打开浏览器（FR-C-101） | Windows `Process.Start`；Linux 打印 URL（有 DISPLAY 时尝试 xdg-open） |

## 4. 关键启动/生命周期流程

### 4.1 客户端冷启动

```
服务启动
 → 读取本地状态文件（设备凭据/配置，见 03 §5）
 → 未注册？→ 启动本地 Web（向导模式）等待用户完成注册（FR-C-101/102/103）
 → 已注册：
     → NicManager 应用虚拟 IP（失败→降级告警，不阻断）
     → ControlClient 建立控制通道（Hello/鉴权握手，见 02 §2.3）
     → 同步映射配置，恢复各映射初始状态（禁用→空闲）
     → 启用中的映射进入"打洞中"（按需：仅当有本地应用连接时才打洞？——否，启用即打洞，PRD FR-C-306）
```

### 4.2 崩溃自愈（FR-C-902）

- Windows 服务恢复选项 / systemd `Restart=always` + `RestartSec=5`；
- 进程内未捕获异常经日志落盘后快速失败，由系统拉起；状态恢复依赖本地状态文件 + 服务端配置同步（幂等）。

### 4.3 升级（FR-C-904）

- 控制通道 Hello 返回 `ProtocolVersionNotSupported` → 客户端请求服务端**稳定更新接口**（FR-S-804，走 HTTP GET `http://server:7500/updates/latest`？——否，7500 仅本机。设计：更新信息经控制协议 `UpdateInfoRequest` 消息获取，协议版本号保留在首个握手消息中永不变更语义）→ 本地 Web 渲染 `/upgrade` 页面并自动打开浏览器。

> 设计细节：`Hello.protocolVersion` 字段位置与语义**冻结**（不随协议演进改动），确保旧客户端永远能完成版本探测并拿到升级指引（02 §2.3）。

## 5. 进程间端口与地址汇总（TD-07，全部可配置）

| 端点 | 绑定 | 用途 |
|---|---|---|
| Server :7000/TCP | 0.0.0.0 | 控制通道（注册/心跳/信令/配置） |
| Server :3478/UDP+TCP | 0.0.0.0 | STUN Binding（带设备认证） |
| Server :7010+/UDP+TCP | 0.0.0.0（可配端口段） | 中继 |
| Server :7500/HTTP | **127.0.0.1** | Web 后台（远程经 F7 映射接入） |
| Client :7100/HTTP | **127.0.0.1** | 本地 Web 管理 |
| Client 虚拟 IP | 虚拟网卡 | 映射监听地址（如 100.64.0.x） |
