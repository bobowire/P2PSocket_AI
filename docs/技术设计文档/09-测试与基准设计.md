## 2. 关键测试设计

### 2.1 协议与加密单测

- PTP 帧编解码往返；counter 重放/回退必须拒绝（SEC-12）；
- 握手：中间人篡改 THello2 字段 → TConfirm 校验失败；
- PCP：seq 重复、ts 超窗、HMAC 错误 → 断连计数；
- STUN：RFC5389 测试向量 + DEVICE-AUTH 错误密钥静默丢弃；
- **时钟对齐（OQ-12）**：offset 计算（注入已知 RTT 验证 RTT/2 补偿精度）、TIME_SKEW 后重校准重试一次成功；
- **ECIES（OQ-15）**：RegisterAck 密文加解密往返、篡改密文 → 客户端解密失败拒绝；
- **凭据恢复（OQ-14）**：同 mac_code 离线重注册 → 覆盖式恢复（deviceId/远程码/分组保留、存量映射不失效）；在线重注册 → 4004 拒绝；
- **邀请码（OQ-17）**：生成字符集/长度/唯一性冲突重试、撤销即失效。

### 2.2 NAT 模拟器（集成测试核心装置）

`tests/NatSimulator`：用户态 UDP/TCP 代理模拟 NAT 行为，注入到客户端与 STUN/对端之间：

| 模式 | 行为 | 用于验证 |
|---|---|---|
| FullCone | 同一内部端点 → 固定外部端点，任意外部可入 | UDP 打洞必成功基线 |
| RestrictedCone | 固定映射，仅允许曾出站联系过的对端入站 | UDP 打洞（双向发包命中） |
| PortRestricted | + 限制端口 | 同上 |
| SymmetricRandom | 随机分配外部端口 | 打洞必失败 → 中继回退路径（A-6，UDP/TCP 两变体） |
| SymmetricSequential | 每次出站新连接分配 **+1 递增** 外部端口 | **TCP 端口预测 +N 命中**（A-5 自动化；UDP 同构变体验证顺序分配语义） |
| UdpBlocked | 丢弃全部 UDP 出站（不建映射） | 迫使 TCP 打洞 / TCP 中继承载（FR-S-704） |

**TCP 模拟机理与边界（TD-17，交付语义 TD-21 随 M2-30 定案）**——用户态无法让真实 SYN 在两台内核间交叉，TCP NAT 模拟采用"导演 + 桥接"：

- **代理一切**：NatSimulator 同时代理 STUN(3478/TCP) 与全部出站连接（测试注入：客户端的 STUN/打洞目标地址均指向它）；Binding 响应的 `XOR-MAPPED-ADDRESS` 由其**改写**为自己记录的分配端口——"公网端口"完全由模拟器导演；每客户端独占端口子段（默认 100/客户端），打洞窗口互不重叠；
- **源端口精确控制**：出站连接经导演窗口 accept 时按序分配外部端口——Sequential 模式自子段基址 +1 递增、Random 模式随机——端口预测的前提（顺序分配规律）由此可控复现；探测后在分配端口 E+0..E+4 开窗监听（N≤5 的预测目标全落窗内）；
- **入站"命中"= 应用层终结桥接（TD-21）**：模拟器接受入站 TCP 连接（代三方握手），按目标端口映射交付——**探测映射**交付探测时的内部端点 listen（任意注册来源可入、多次可入——N=1 直连 STUN 端口前提；**扰动窗内毒化**为无人监听端口——扇首 +0 腿的必败因子，见下条）；**出站映射**按 APDF 精确身份过滤（入站连接在源侧新分配的外部端口须等于映射目的地端口——对称 rendezvous 四元组交叉），命中即与映射套接字双向桥接（同对幂等去重）——对 PTP 协议透明，但对内核不可见（非真实 SYN 穿越）；miss（无映射/listen 未起）前 600ms 有界重试=模拟 SYN 重传（真实 NAT 靠 ~1s 重传获得同样容忍度）；
- **命中代数**：命中 ⟺ |ΔN|≤1 或 min(N_A,N_B)=1；必 miss ⟺ |ΔN|≥2 且 min(N)≥2（N=1 参与的不对称对经探测 listen 路径命中，非必 miss）。**miss 断言口径（M2-31 修正；扇形口径 2026-10-25 随 02 §5.2⑥ 重写）**：协议统一双方 N（TD-13/20，0x70 上送→服务端回填→双方同 N）→ N_A≠N_B 在真实路径不存在——不对称 miss 以**单测级注入**断言（M2-16）；A-5 场景级失配以 **NAT 时序扰动**等效呈现（模拟器 `punchPerturbation`：对端 connect 瞄 P+[0..N−1] **全扇**（02 §5.2⑥，旧单点 +(N−1) 口径废止），扰动窗内注入两层必败因子——①**探测门毒化**：探测映射交付目标改指无人监听端口（APDF：探测映射对第三方不可入），封扇首 +0 腿；②**外来占位** s 条占用 P+1..+s（内部指向无人监听端口），封 +1..+(N−1) 各腿），s≥N−1 + 门毒化 ⟺ 全扇必 miss；`persistPerturbation=true` 扰动不随首探测耗尽（每次探测均封门+占位）=**重打永败世界**（M2-37/38/32），缺省一次性（M2-19 首打 miss、重打门恢复开放干净命中）；
- 因此**可验证**：端口预测逻辑、N 路对称性、胜出/取消逻辑、扇形 [0..N−1] 各偏移命中；**不可验证**：真机 SYN 重传对发起时差的覆盖能力——保留为 A-5 真机手工样本（有条件环境补测，§3.4）；
- UDP 无连接，无此边界（NAT 行为即转发规则本身）。

部署注意：模拟端口段（默认 20000-21000）需从 OS 临时端口排除，防止系统抢占扰动顺序分配——Windows：`netsh int ipv4 add excludedportrange protocol=tcp startport=20000 numberofports=1001`；Linux：将 `net.ipv4.ip_local_port_range` 调开该段。该命令进 CI 环境准备脚本（08 §4）。

直连候选测试缝（v1.63，NET-76）：NatSimulator 回环别名（127.0.0.x）fabric 全互通——本机网卡候选会击穿「跨 NAT 不可直达」的必败场景前提（A-5 miss / A-6 回退等），故场景基架 StartRuntimeAsync 默认注入 `ClientRuntimeOptions.LocalIpEnumeratorOverride = 空枚举`（候选关、NAT 语义保持），同网段直连路径由显式开启的场景驱动（ScenarioIntegrationTests.S54：M2_18 同拓扑+端口扰动必 miss+候选开 → direct+echo 往返，对照组候选关 → failed）；候选构造/扇出/钉定/拒连重试/分账由单元级覆盖（TcpPunchFleet 直连命中与重试与分账与 accept 扇出、Puncher 恒等映射与映射平移、PunchTests UDP 双假映射 pin 回程、SignalingTests 候选透传与旧端 null）。

KCP 承载测试设计（vM6，NET-77，11 号 §11 落地）：
- **受控介质单测**：KCP 协议核属性矩阵（Core 14 例——受控丢包 0~50%×乱序×重复下可靠有序性质[零缺段/零重复交付/零死锁、闭合窗收敛、ACK 全确认]＋对拍参考行为关键场景[RTO 退避序列 nodelay ×1.5 对拍 200/500/950/1625ms、快重传先于 RTO、FASTACK_CONSERVE]＋WINS 裁剪的窗口重开死锁补偿；时钟注入确定性）；KcpTunnelTransport 受控介质（真实 loopback socket 对——帧型×conv 路由穷举/unknown-conv 拒绝/conv 上限降级/Adopt 所有权/裸路径白名单闭包[迟到 STUN 形似帧不杀隧道红证]/裸队列 DropOldest 守恒）；会话级全帧型往返（外驱动握手→Adopt→FromEstablishedKeys 生产流 rehearsal——OPEN/OPEN_OK/OPEN_FAIL/DATA/WINDOW/CLOSE/REKEY/REKEY_ACK/PING/KEEPALIVE/UDP_DGRAM/FRAG+三缝 conv 生命周期断言）。
- **弱网红绿矩阵**（立项级证据，IntegrationTests 会话级 8 例）：真实 UdpNatSimulator 注入旋钮（丢包率/乱序深度/重复率/延迟抖动/突发档=200ms 窗连片丢+相位对齐）——KCP 组 1/5/20% 丢包×乱序×100ms 抖动+突发档全格**零缺段/零 credit 挂起/会话存活**；裸 UDP 对照组同条件**复现 M2-38 家族故障（红证）**；黑洞档（全丢）KCP 重传不伪造活性——KEEPALIVE 3×miss 断链照常、净网恢复重建。
- **场景两态**：`ClientRuntimeOptions.DisableKcpBearer`（kill-switch 测试缝）驱动 kcp on/off 两态——世界级 A-3 形态 off 态布线回归 + Puncher 双角色混布矩阵（新新=KCP/单旧=裸/kill-switch 回 0/旧服务端剥字段=双端同判 false 无脑裂，PuncherKcpBearerTests 6 例）；Integration 114 基线不减。
- **ReplayWindow 4096 回归**（Core）：跨 conv 乱序深度注入（4000 深度全接受）/出窗拒绝分界/跨字边界重复拦截/大跨跳整窗重置。

## 3. 性能基准方案（NFR-11，交付《基准测试报告》）

### 3.1 吞吐

```
方法：iperf3 -c 虚拟IP:映射端口（经隧道） vs iperf3 直连基线
场景矩阵：{直连UDP, 直连TCP, 中继UDP, 中继TCP} × {1并发流, 4并发流}
KCP 承载五组对照（M6-07，NET-77）：裸 UDP（现状基线）/ KCP nc=1 默认 / KCP nc=0 对照 / TCP 参照 / 裸 UDP 弱网对照（红证）——P2P.Bench `kcp` 段（KcpBearerBench：四组×吞吐三档+PING µs+建立耗时+CPU；调参矩阵 24 cell；丢包-吞吐曲线 0~30% 完整性恒断言）
环境：同机房两台 VPS + 一台服务端（报告注明规格）
指标：Mbps、CPU%、内存；单文件大对象 + 小包（1KB）两档
```

### 3.2 延迟

```
ICMP 对照不可用（流隧道）→ PTP PING（0x06）测隧道 RTT vs 系统 ping RTT，差值=封装加密开销；
报 NFR-14"打洞建立耗时"：enable → direct 状态的墙钟时间（100 次分布）。
```

### 3.3 规模与稳定性

```
设备数：注册 500 设备（模拟心跳）→ 服务端内存/CPU、列表推送延迟；0x40 分页（hasMore 循环拉全量）正确性（OQ-16）；
映射并发：单隧道 100 channel 并发传输，验证复用与背压无死锁；
打洞排队（OQ-11）：多目标映射同时 enable → PunchScheduler 串行完成、STUN 探测与打洞互不交叉污染预测基准；
稳定性：24h 持续传输 + 周期 REKEY + 强制中继↔直连切换（NET-75 排水验证，无数据错乱）。
```

### 3.4 打洞成功率（A-5 数据源）

NatSimulator 各模式 × N=1~5 的成功率矩阵；有条件时补充真实环境（家宽/4G/办公网）手工样本。

### 3.5 UDP 承载可靠化门禁（NET-77，11 号 §12 决议⑥，M6-07 实证 PASS）

- **性能闸**：0% loss 本机回环，KCP 吞吐 ≥ 裸 UDP **70%** 且 PING RTT 增量 ≤ **5ms**（语义=好网络下别劣化）——**M6-07 实测：吞吐比 70.7%、PING p50 增量 0.052ms → PASS**（基准报告 v1.1 §5.1；nc=0 调参余量 87.7%）。
- **正确性闸**：弱网矩阵全格绿——丢包 0/1/5/20% × 乱序 × 100ms 抖动 + **突发档**（200ms 窗连片丢）每格零缺段/零 credit 挂起/会话存活，裸 UDP 对照组同条件红证——M6-06 实测 8/8 全绿。
- 高丢包段**不设绝对吞吐门禁**（拍数字锁死自己）——丢包-吞吐曲线入基准报告（0→30% 完整性恒成立，30% 档 45.6Mbps）；持续 >20% 丢包=网络不可用，职责归 KEEPALIVE 3×20s 断链。
- 不达线回调参矩阵 → 移植核对层（对照 skywind3000/kcp 重查数学）；TD-24 L1 口径如实标注（本机回环≠真实网络）。
