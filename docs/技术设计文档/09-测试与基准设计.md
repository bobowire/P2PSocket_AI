## 2. 关键测试设计

### 2.1 协议与加密单测

- PTP 帧编解码往返；counter 重放/回退必须拒绝（SEC-12）；
- 握手：中间人篡改 THello2 字段 → TConfirm 校验失败；
- PCP：seq 重复、ts 超窗、HMAC 错误 → 断连计数；
- STUN：RFC5389 测试向量 + DEVICE-AUTH 错误密钥静默丢弃；
- **时钟对齐（OQ-12）**：offset 计算（注入已知 RTT 验证 RTT/2 补偿精度）、TIME_SKEW 后重校准重试一次成功；
- **ECIES（OQ-15）**：RegisterAck 密文加解密往返、篡改密文 → 客户端解密失败拒绝；
- **凭据恢复（OQ-14）**：同 mac_code 离线重注册 → 覆盖式恢复（deviceId/远程码/分组保留、存量映射不失效）；在线重注册 → 4004 拒绝；
- **邀请码（OQ-17）**：生成字符集/长度/唯一性冲突重试、撤销即失效。

### 2.2 NAT 模拟器（集成测试核心装置）

`tests/NatSimulator`：用户态 UDP/TCP 代理模拟 NAT 行为，注入到客户端与 STUN/对端之间：

| 模式 | 行为 | 用于验证 |
|---|---|---|
| FullCone | 同一内部端点 → 固定外部端点，任意外部可入 | UDP 打洞必成功基线 |
| RestrictedCone | 固定映射，仅允许曾出站联系过的对端入站 | UDP 打洞（双向发包命中） |
| PortRestricted | + 限制端口 | 同上 |
| SymmetricRandom | 随机分配外部端口 | 打洞必失败 → 中继回退路径（A-6，UDP/TCP 两变体） |
| SymmetricSequential | 每次出站新连接分配 **+1 递增** 外部端口 | **TCP 端口预测 +N 命中**（A-5 自动化；UDP 同构变体验证顺序分配语义） |
| UdpBlocked | 丢弃全部 UDP 出站（不建映射） | 迫使 TCP 打洞 / TCP 中继承载（FR-S-704） |

**TCP 模拟机理与边界（TD-17，交付语义 TD-21 随 M2-30 定案）**——用户态无法让真实 SYN 在两台内核间交叉，TCP NAT 模拟采用"导演 + 桥接"：

- **代理一切**：NatSimulator 同时代理 STUN(3478/TCP) 与全部出站连接（测试注入：客户端的 STUN/打洞目标地址均指向它）；Binding 响应的 `XOR-MAPPED-ADDRESS` 由其**改写**为自己记录的分配端口——"公网端口"完全由模拟器导演；每客户端独占端口子段（默认 100/客户端），打洞窗口互不重叠；
- **源端口精确控制**：出站连接经导演窗口 accept 时按序分配外部端口——Sequential 模式自子段基址 +1 递增、Random 模式随机——端口预测的前提（顺序分配规律）由此可控复现；探测后在分配端口 E+0..E+4 开窗监听（N≤5 的预测目标全落窗内）；
- **入站"命中"= 应用层终结桥接（TD-21）**：模拟器接受入站 TCP 连接（代三方握手），按目标端口映射交付——**探测映射**交付探测时的内部端点 listen（任意注册来源可入、多次可入——N=1 直连 STUN 端口前提）；**出站映射**按 APDF 精确身份过滤（入站连接在源侧新分配的外部端口须等于映射目的地端口——对称 rendezvous 四元组交叉），命中即与映射套接字双向桥接（同对幂等去重）——对 PTP 协议透明，但对内核不可见（非真实 SYN 穿越）；miss（无映射/listen 未起）前 600ms 有界重试=模拟 SYN 重传（真实 NAT 靠 ~1s 重传获得同样容忍度）；
- **命中代数**：命中 ⟺ |ΔN|≤1 或 min(N_A,N_B)=1；必 miss ⟺ |ΔN|≥2 且 min(N)≥2（N=1 参与的不对称对经探测 listen 路径命中，非必 miss）。**miss 断言口径（M2-31 修正）**：协议统一双方 N（TD-13/20，0x70 上送→服务端回填→双方同 N）→ N_A≠N_B 在真实路径不存在——不对称 miss 以**单测级注入**断言（M2-16）；A-5 场景级失配以 **NAT 时序扰动**等效呈现（模拟器 `punchPerturbation`：对端首次探测后、Fleet 连接前注入 s 条探测型外来流占用端口序列，内部指向无人监听端口 → 命中即 listener_refused miss），s≥N−1 ⟺ 不对称必 miss 区；
- 因此**可验证**：端口预测逻辑、N 路对称性、胜出/取消逻辑、`(N−1)` 偏移命中；**不可验证**：真机 SYN 重传对发起时差的覆盖能力——保留为 A-5 真机手工样本（有条件环境补测，§3.4）；
- UDP 无连接，无此边界（NAT 行为即转发规则本身）。

部署注意：模拟端口段（默认 20000-21000）需从 OS 临时端口排除，防止系统抢占扰动顺序分配——Windows：`netsh int ipv4 add excludedportrange protocol=tcp startport=20000 numberofports=1001`；Linux：将 `net.ipv4.ip_local_port_range` 调开该段。该命令进 CI 环境准备脚本（08 §4）。

### 2.3 集成场景脚本（对应验收 A-x）

```
A-1 首启注册（两平台）：向导注册 → 设备在线 → 网卡/虚拟 IP 就绪
A-2 同账号双设备发现：同账号两台设备互见（0x40 列表/在线状态/开放网段摘要/remoteCode）
A-3 UDP 打洞直连：NatSimulator(FullCone × RestrictedCone) → 映射 direct → TCP 回环载荷校验
A-4 端口隔离：本机 127.0.0.1:8080 占用 + 虚拟IP:8080 映射并存互不干扰
A-5 TCP 打洞：SymmetricSequential 下 N=1~5 逐一跑，输出命中率矩阵（进基准报告）；失配 miss 以 punchPerturbation 时序扰动等效（N_A≠N_B 被协议统一 N 排除，TD-13/20）——已自动化（M2-31）
A-6 中继回退：SymmetricRandom；目标设备 B 回退开（peers.json）→ relay 可用；目标设备 C 关 → failed
A-7 哑节点：passive 模式直连服务端 API 发主动类消息 → 2002 + 审计记录
A-8 白名单：段内放行/段外 4002/移除后存量映射 invalid
A-9 远程码重置：旧码建映射失败（4003）；新码恢复
A-10 健壮性：kill -9 / 服务重启 → 状态恢复（网卡、映射、控制通道重连）
A-11 卸载清理（双平台手工）：卸载后服务/程序/驱动适配器按约定清除，数据目录询问保留
A-12 服务端 Web 远程接入（手工）：服务端机器部署客户端 → F7 映射接入 7500 可管理；公网扫描 7500 不可达
```

## 3. 性能基准方案（NFR-11，交付《基准测试报告》）

### 3.1 吞吐

```
方法：iperf3 -c 虚拟IP:映射端口（经隧道） vs iperf3 直连基线
场景矩阵：{直连UDP, 直连TCP, 中继UDP, 中继TCP} × {1并发流, 4并发流}
环境：同机房两台 VPS + 一台服务端（报告注明规格）
指标：Mbps、CPU%、内存；单文件大对象 + 小包（1KB）两档
```

### 3.2 延迟

```
ICMP 对照不可用（流隧道）→ PTP PING（0x06）测隧道 RTT vs 系统 ping RTT，差值=封装加密开销；
报 NFR-14"打洞建立耗时"：enable → direct 状态的墙钟时间（100 次分布）。
```

### 3.3 规模与稳定性

```
设备数：注册 500 设备（模拟心跳）→ 服务端内存/CPU、列表推送延迟；0x40 分页（hasMore 循环拉全量）正确性（OQ-16）；
映射并发：单隧道 100 channel 并发传输，验证复用与背压无死锁；
打洞排队（OQ-11）：多目标映射同时 enable → PunchScheduler 串行完成、STUN 探测与打洞互不交叉污染预测基准；
稳定性：24h 持续传输 + 周期 REKEY + 强制中继↔直连切换（NET-75 排水验证，无数据错乱）。
```

### 3.4 打洞成功率（A-5 数据源）

NatSimulator 各模式 × N=1~5 的成功率矩阵；有条件时补充真实环境（家宽/4G/办公网）手工样本。
