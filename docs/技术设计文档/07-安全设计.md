# 07 · 安全设计

> 所属文档集：[README](README.md)　实现 PRD [07-安全需求](../prd/07-安全需求.md)（SEC-xx）。整体策略：**不依赖 TLS**（D21），全部安全能力构建于 .NET 内置密码学原语之上（TD-04）。

## 1. 密钥体系总览

| 密钥 | 生成 | 存储 | 用途 | 生命周期 |
|---|---|---|---|---|
| 设备静态密钥对（P-256） | 客户端首次注册时生成 | 私钥：客户端本地（DPAPI/0600）；公钥：服务端 devices 表 | 隧道握手身份绑定（static-static ECDH） | 设备身份存续期 |
| deviceSecret（32B） | 服务端注册时 CSPRNG 生成，**ECIES 加密下发**（OQ-15，见 §5） | 双端（服务端库内 / 客户端本地加密） | 控制通道 HMAC、STUN 认证 | 重置/解绑/凭据恢复时轮换 |
| connMacKey | 每次控制连接握手 HKDF 派生 | 内存 | 控制消息 seq HMAC | 单连接 |
| 会话密钥（发送/接收各 32B） | 每次隧道握手 HKDF 派生 | 内存 | PTP 帧 AES-256-GCM | TTL 3600s（REKEY 轮换，SEC-14） |
| 用户口令哈希 | 注册时 PBKDF2-SHA256（100k 迭代、16B 盐） | 服务端 users 表 | Web 登录 | 改密时重建 |

派生函数统一：`HKDF-SHA256(ikm, salt, info, len)`；随机源统一 `RandomNumberGenerator`（CSPRNG）。

## 2. 数据面加密（SEC-11/12，02 §4）

- AEAD：`System.Security.Cryptography.AesGcm`（AES-256-GCM，硬件加速），tag 16B；
- nonce：64bit counter 小端填充 12B，**每方向严格单调**；接收端维护滑动窗口（64）拒绝重复/回退（防重放）；
- AAD 绑定帧头（ver/type/channelId/len），防帧裁剪与类型篡改；
- 机密性/完整性/防重放三项能力由此满足；中继路径下密钥不变 → **服务端不可解密**（SEC-11 的中继不可解密要求）。

## 3. 握手与身份防冒充（SEC-21，02 §4.1）

- 双重 ECDH：`ECDH(ephA,ephB)`（会话独立性）⊕ `ECDH(staticA,staticB)`（身份绑定）→ HKDF 派生会话密钥；
- 静态公钥经服务端 PunchInvite 下发 → 信任来源是服务端（SEC-13"控制面协助交换"）；
- 握手消息带 HMAC（以 static-static 共享密钥为 IKM 派生的握手密钥）验证，防中间人篡改握手报文；
- 冒充者无目标设备私钥 → 无法通过 TConfirm 验证 → 会话建立失败。

## 4. 控制通道安全（SEC-22，02 §2）

- 连接级：Hello 挑战（nonceC/nonceS）→ Proof(HMAC(deviceSecret)) → 派生 connMacKey；
- 消息级：每条消息 `seq 单调递增 + ts ±120s 窗口 + HMAC-SHA256`；校验失败立即断连并记审计；
- 重放防御三层：seq（连接内）、ts（跨连接窗口）、nonce 去重（STUN 侧缓存 5min）；
- **时钟对齐（OQ-12）**：Hello 阶段不校 ts（尚无共享时间基准）；HelloAck 携带 serverTs，客户端按 RTT/2 补偿计算 offset 后再发 Proof；超窗回 5005 TIME_SKEW 供重校准重试——消除"时钟偏差死锁"（原设计 Proof 先于校准被拒，形成无法进入协议的环）；0x30 Ack 周期性重校 offset 跟踪漂移。

## 5. 注册与滥用防护（PRD 风险 T3/R2）

- 未注册设备的 `Register` 无 HMAC（尚无密钥）：防护 = ①开放注册开关（server_config）②单 IP 注册频率限制（如 10 次/小时，内存令牌桶）③设备总数上限（server_config `max_devices`，默认 500，OQ-13 后虚拟 IP 不再构成天然上限）④管理员事后禁用/解绑 ⑤同 mac_code 重注册且原设备在线 → Error 4004 拒绝（防伪造 MAC 抢注在线身份，OQ-14）⑥RegisterAck 的 deviceSecret 以客户端 staticPubKey **ECIES 加密下发**（ECDH(ephS, staticC) + HKDF + AES-256-GCM，防注册链路窃听，OQ-15）；
- MAC 识别码仅作为注册输入，**权威身份是签发的 deviceId**（D6）：克隆机器拿不到原设备私钥与 deviceSecret，无法冒充在线设备；凭据丢失后的重注册走覆盖式恢复（OQ-14：离线方可覆盖，在线必须管理员解绑）；
- 服务端数据库文件权限：Linux `0600`（服务账户）/Windows ACL 仅服务账户与 Administrators。

## 6. 凭据本地存储（SEC-23）

| 平台 | 方案 |
|---|---|
| Windows | `ProtectedData`（DPAPI，机器范围）加密 deviceSecret 与静态私钥后写入 state.json |
| Linux | state.json `0600`、目录 `0700`（root 或专用服务账户） |

## 7. 授权执行点（SEC-52，PRD 05 §4 判定链）

| 层 | 执行位置 | 失败动作 |
|---|---|---|
| L1 能力模式 | 服务端 ControlSession 分发器 | Error 2002 + 审计 |
| L2 目标授权 | 服务端 Authorizer（SQL：账号设备 ∪ 共同分组） | Error 4001 + 审计 `punch_deny` |
| L3 地址白名单 | 服务端（下发 PunchInvite 前）+ 对端 MappingEngine 执行点双重校验 | Error 4002 + 审计 `mapping_deny` |
| 远程码 | 仅查找别名，不构成授权（D7） | Error 4003 |
| 授权失效事件 | 登出/退组/白名单移除/码重置/禁用 → 服务端推送失效（0x75 Invalidation，02 §2.4）→ 双端映射状态机 → invalid | 停止转发 + 双端提示 |

## 8. 管理面（PRD 07 §4 决策的落实）

- 客户端本地 API：仅 `127.0.0.1` 监听 + 本机回环信任（无鉴权，风险 T7/R1 已知情接受）；
- 服务端 Web：仅本机监听；管理员 Cookie 会话（HttpOnly/SameSite=Strict）；远程管理仅经 F7 隧道；
- 升级引导链路（FR-C-904）无认证依赖：UpdateInfo 为只读公开内容（版本号与指引），不泄露业务数据。

## 9. 残余风险与技术对策对照（PRD 07 §6）

| PRD 风险 | 本设计的对策 | 残余 |
|---|---|---|
| R1 HTTP 明文 | 决策维持；控制通道有 HMAC 完整性（无机密性——信令含端点信息，属已知情接受范围） | 信令明文可见（非业务数据） |
| R2 MAC 重复/伪造 | deviceId + 私钥权威身份（§5）；在线设备拒绝覆盖式重注册（4004） | 无 |
| R3 TCP 预测命中率 | 并发路数 N 可配（1~5），A-5 实测调优 | 随机型 NAT 依赖中继 |
| R4 UDP 被封 | TCP 打洞 + TCP 中继承载（FR-S-704） | 无混淆（SEC-15 扩展位保留，PTP 帧外层可插拔） |
| R6 admin/admin | 首登提示改密；命令行重置工具列入 M2 交付（`--reset-admin`） | 弱口令未强制修改 |
| R7 注册链路主动 MITM | RegisterAck 经 ECIES 加密 deviceSecret（OQ-15，防窃听）；攻击者若在注册期**替换**客户端 staticPubKey，可令服务端加密的 secret 对其可读并接管该新注册身份 | 一次性窗口攻击，需注册期持续 MITM；已知情接受；后续可选：服务端 Web 展示设备公钥指纹供管理员人工核对 |
