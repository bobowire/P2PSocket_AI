# 08 · 构建与部署设计

> 所属文档集：[README](README.md)　落实 NFR-31~36、NFR-51~53。

## 1. 版本与仓库

- 语义版本 `Major.Minor.Patch`，与 `protocolVersion` 独立演进（协议兼容策略见 02 §7）；
- 构建号注入：`SOURCE_DATE_EPOCH` + git commit hash 短串写入 `ThisAssembly.Metadata`；
- Git 仓库单仓（解决方案结构见 01 §2）；CI 见 §4。

## 2. 构建流水线（本地等价脚本）

```
① dotnet build -c Release                     # C# 编译 + 单测可在 CI 分开
② pnpm --filter @p2p/client-app build         # Vue 产物
   pnpm --filter @p2p/server-app build
   → 输出复制至 P2P.Client/wwwroot、P2P.Server/wwwroot（vite outDir 直指）
③ dotnet export-ts（反射 DTO）→ ui-shared/types/api.d.ts   # 类型同源（06 §5，顺序在②前）
④ dotnet publish:
   服务端：dotnet publish src/P2P.Server -c Release -r linux-x64 \
             -p:PublishSingleFile=true -p:SelfContained=true -o out/server
   客户端：同上，rid ∈ { win-x64, linux-x64, linux-arm64 }
⑤ 打包（§3）
```

单文件自包含要点：

- `PublishSingleFile` + `IncludeNativeLibrariesForSelfExtract`（Wintun.dll 走程序目录分发而非内嵌，见 §3.1）；
- SPA 静态资源为 EmbeddedResource → 进程序集 → 单 exe 完整（NFR-31）；
- NativeAOT：列为可选优化项（反射/EF Core 适配成本，暂不启用）。

## 3. 交付物

### 3.1 Windows 客户端安装包（Inno Setup）

```
P2PClient-Setup-{ver}-x64.exe
 ├─ 复制 p2p-client.exe、Wintun.dll → %ProgramFiles%\P2PClient\
 ├─ 创建 Windows 服务 "P2PClient"（sc create … start=auto）→ 启动（FR-C-901）
 ├─ 数据目录 %ProgramData%\P2PClient（ACL: SYSTEM+Administrators）
 ├─ 静默参数 /VERYSILENT（NFR-32）；卸载：停服务→删程序/服务/驱动适配器→数据目录询问保留（A-11）
 └─ 驱动说明：Wintun 为用户态驱动 DLL（无内核驱动安装步骤），随卸载直接删除
```

### 3.2 Linux 客户端（deb + rpm）

```
p2p-client_{ver}_amd64.deb / _arm64.deb、p2p-client-{ver}.x86_64.rpm
 ├─ /usr/bin/p2p-client
 ├─ /etc/p2p-client/（配置样例）、/var/lib/p2p-client/（状态，0700）
 └─ systemd: p2p-client.service（Restart=always, RestartSec=5, After=network-online）
```

### 3.3 服务端

```
① 单文件二进制 p2p-server（linux-x64 / win-x64）
② Docker 镜像 p2p-server:{ver}（NFR-34）：
   FROM mcr.microsoft.com/dotnet/runtime-deps:10.0 → 复制单文件 + ENTRYPOINT
   卷：/data（p2p.db + 日志）；端口 7000/3478(udp+tcp)/7010-7020(udp+tcp)
   Web 接入修正：容器内 webBind 需设 0.0.0.0，compose 以 "127.0.0.1:7500:7500" 映射到宿主回环
   ——容器内绑 127.0.0.1 宿主完全不可达（F7 断链）；回环前缀映射保持"不对公网监听"（D11），
   禁止裸 "7500:7500" 暴露
   docker-compose.yml 示例随文档交付
③ 初始化：首次启动建库 + 内置 admin/admin + 默认分组（FR-S-203/301）
```

## 5. 配置文件设计

### 5.1 服务端 `appsettings.json`（进程级，08 与 03 §2.8 分工：端口/路径在文件，业务开关在库）

```jsonc
{
  "listen": { "control": 7000, "stunUdp": 3478, "stunTcp": 3478,
               "relayPorts": [7010, 7020], "web": 7500, "webBind": "127.0.0.1" },
  "database": { "path": "data/p2p.db" },
  "heartbeat": { "timeoutSec": 30 },
  "punch": { "defaultConcurrency": 3, "timeoutSec": 10 },
  "relay": { "idleTimeoutSec": 90 },
  "logging": { "level": "Information", "retentionDays": 14 }
}
```

### 5.2 客户端 `settings.json`（首启向导写入；本地 Web 可改，04 §2.1）

```jsonc
{
  "serverAddrs": [ "p2p.example.com:7000", "203.0.113.10:7000" ],  // 域名/主备多候选，依次尝试（FR-C-604）
  "localWebPort": 7100,
  "punchConcurrency": 3,          // 1~5，OQ-1 决议
  "keepaliveSec": 20,
  "reconnect": { "minSec": 1, "maxSec": 30 }
}
```

命令行参数优先级高于配置文件（`--server`、`--reset-admin`（服务端，07 §9）、`--console` 前台运行调试）。

启动配置校验（NFR-35）：解析失败/端口越界/punchConcurrency 越界（1~5）/网段格式非法等**拒绝启动并输出明确诊断**（字段名 + 合法范围 + 修复建议），不允许带病静默运行；客户端校验失败但本地 Web 端口本身合法时，Web 仍可用以展示错误页。

## 6. 可观测性（NFR-51~53）

- Serilog sink：控制台（服务模式可选关）+ 滚动文件（`logs/app-.log`，10MB×14 个）；
- 结构化字段：`sessionId`、`mappingId`、`channelId`、`deviceId`、`remoteCode`（脱敏后段）——本地 Web 日志页按字段过滤；
- 关键计数器（进程内 Prometheus 格式暴露可选，M3）：`punch_total{result}`、`relay_bytes_total`、`stun_queries_total`、`tunnel_active_sessions`；
- 诊断命令：`p2p-client diagnostics`（控制台输出连通性/STUN/网卡状态，便于无浏览器环境排障，NFR-52 补充）。

## 7. 升级路径（FR-C-904）

- 客户端：停服务 → 替换 exe（配置与状态在程序目录外，天然保留）→ 起服务；
- 服务端：同理 + EF Core 迁移自动执行（03 §6）——**迁移与幂等种子（含 server_config 缺键补齐）在 Program 容器构建前先行执行**（M3-18 实机部署发现：Host 首次解析 IHostedService 即构造全部托管服务实例，ServerWebHostService ctor 注入的 StunService/RelayService 工厂读 server_config 早于 ServerHostService.StartAsync 的初始化——存量库缺新增键[stun_alt_addr]或全新库未建表都会在读点崩溃；先行 Initialize 后任何读取点必然晚于它）；
- 协议不兼容 → 客户端打开 `/upgrade`（04 §2.7），指引从服务端 UpdateInfo 获取（链路冻结设计见 02 §7）。
