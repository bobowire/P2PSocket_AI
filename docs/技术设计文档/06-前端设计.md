# 06 · 前端设计

> 所属文档集：[README](README.md)　技术栈：Vue 3（`<script setup>` + TS）+ Element Plus + Vite + Pinia（TD-02）。

## 1. 工程结构

```
web/
├─ ui-shared/                   # pnpm workspace 包 @p2p/ui-shared
│  ├─ components/               #  StatusTag(映射状态)、RateChart(ECharts 封装)、
│  │                            #  DeviceCard、CodeText(远程码复制)、ConfirmInput
│  ├─ composables/              #  useApi(axios 实例/错误码拦截)、useWs(重连+事件订阅)、
│  │                            #  useRealtimeStats(1s 速率)
│  ├─ layouts/                  #  AdminLayout(侧边栏+顶栏)
│  └─ types/                    #  生成的 API 类型（§5）
├─ client-app/                  # 客户端本地 Web（127.0.0.1:7100）
└─ server-app/                  # 服务端 Web 后台（127.0.0.1:7500）
```

- 两个 app 仅路由与页面不同，全部 UI 资产来自 ui-shared；
- 包管理 pnpm workspace；Node ≥ 20 LTS。

## 4. 状态与实时（TD-16：REST 是真相、WS 只是提示）

WS 事件可能丢失/乱序/陈旧（断连间隙、多事件竞达），因此**一切状态以 REST 响应为准**，WS 仅充当"该去刷新了"的提示信号：

```
Pinia stores:
  useSystemStore   # /api/system/state + /api/device 轮询 10s
  useAuthStore     # 登录态、能力模式（login_state 事件触发 refetch）
  useMappingStore  # 列表与状态经 REST；速率行内更新（mapping_stats）
  useDeviceStore   # device_list 事件触发 refetch（0x40 分页 hasMore 循环拉全量，OQ-16）
```

**事件分级处理**：

| 级别 | 事件 | 处理 |
|---|---|---|
| 高频数值类 | mapping_stats（1s 速率） | 直接写入 store——下秒覆盖，丢失/陈旧无害 |
| 状态类 | mapping_state / device_list / login_state | **不直接改 store**，仅触发对应资源 refetch（100ms debounce 合并突发） |

M2-28 注记：状态类事件在 refetch 之外经 useWs `onState` 旁路透传原始事件对象（仅提示用途，不改 store）——`mapping_state invalid` → 全局失效提示（0x75 链，列表置灰仍由 refetch 完成）；设备列表 10s 轮询已移除，由 device_list 事件 + onOpen/visibilitychange resync 兜底。

**resync 时机**（丢失事件的兜底）：

- WS `onOpen`（含断线重连成功）→ 全量 refetch（system / mappings / devices）；
- 页面 `visibilitychange → visible`（睡眠唤醒/切回标签页）→ 全量 refetch。

useWs：指数退避重连（1s 起，上限 30s）；本地回环全量拉取毫秒级完成，故**明确否决** seq+增量补发方案（复杂度不匹配收益）。网络断连时页面显示"服务不可达"全局条（本地服务进程存活检测）。

## 5. 类型与 API 一致性

- `P2P.Core` 的 DTO 以 C# record 定义 → 构建脚本 `export-ts`（基于反射）输出 `ui-shared/types/api.d.ts`；
- API 路径常量同源生成，前端禁止手写字符串路径；
- MSW（Mock Service Worker）用于前端独立开发联调。

M3-09 注记：ExportTs 扩展输出**服务端域生成物**（路由表源=`ServerWebHostService.Build(...)` 占位装配提取，DTO 源=`Server/Web/ServerViews.cs` 具名 record——服务端响应原为匿名对象无法反射，先具名化且 JSON 形状逐字段等价、既有回归绿验证）：

- `api-server-paths.ts`（`ServerApiPaths`/`ServerApiEndpoints`/`ServerApiPath`——与客户端生成物**分文件**防常量名冲突）；
- `api-server.d.ts`（`ServerApiEnvelope{code,message,data}`+服务端 DTO 接口；服务端 envelope 字段名=`message`，与客户端 `msg` 不同——useApi unwrap 只取 `r.data.data` 不受影响）；
- DTO 渐进入列：M3-09=LoginResult+Dashboard 族；M3-10=Users/Devices/Groups/GroupRequests/Mappings/Config 全族 17 record（AdminUsers/Devices/Groups/Mappings/System 五 API 匿名对象全部具名化，与客户端域同名 record 以 typeof 全限定消歧六处）；M3-11 随 /relay /system 页补 Relay 族与 AuditLogs；
- 契约测试同款纪律：`server-generated.test.ts` 硬编码 04 §3 服务端 23 端点集与生成物比对（M2-27 生成物漂移教训）。

## 6. 构建与嵌入（与 08 §2 衔接）

```
开发：  pnpm dev（Vite 5173/5174）→ proxy /api、/ws 到 7100/7500
发布：  pnpm build → dist/ → 构建目标复制到 P2P.Client/wwwroot、P2P.Server/wwwroot
        → csproj: <EmbeddedResource Include="wwwroot\**" LogicalName="wwwroot\%(RecursiveDir)%(Filename)%(Extension)" />
运行时：EmbeddedFileProvider 提供静态文件（单文件自包含发布后仍是单一 exe，NFR-31）
```

- 路由模式：hash 模式（嵌入式静态托管无需服务端回退规则）；
- 资源全部相对路径 base `./`。
