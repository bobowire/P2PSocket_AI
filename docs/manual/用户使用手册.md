# P2P 用户使用手册

> 适用版本：1.0.0　依据：NFR-61、设计 08 §8、06 §2/§3　随版交付（M4-08）
> 读者：**客户端使用者**（在自有设备上建立内网穿透映射）与**服务端管理员**（运维公网/内网服务端）。安装部署见 [部署手册](../deploy/)（服务端/Windows/Linux 三篇）；故障排查见[排障指南](troubleshooting.md)（M4-09）。

## 0. 产品与访问入口

### 0.1 产品模型一图流

```
[本机设备] ──映射(本地端口)──▶ [目标设备] ──▶ 目标地址(self 或 内网 IP:端口)
     │                              │
     └──────── 控制面：服务端 ───────┘
   数据面：打洞成功→设备间直连(direct)；不可穿透→经服务端中继(relay)
```

- **远程码**：每台设备的 6 位标识（如 `712152`）。映射用「目标远程码」定位对端设备——类似给设备起的一个短号。
- **虚拟 IP**：注册成功后本机出现虚拟网卡，固定 `100.64.0.2`。**映射监听绑在虚拟 IP 上**（不是 127.0.0.1）——本机访问映射地址须用 `100.64.0.2:端口`，127.0.0.1 上的同端口服务互不干扰。
- **可见性**：两台设备互相可见的前提 = **登录同一账号** 或 **处于同一分组**。互相不可见时一切按远程码的访问都会被拒（4003）。
- **中继回退**：打洞失败（NAT 组合不可穿透）时，若目标设备开启了「中继回退」，流量经服务端转发（relay 态）——服务仍可用，速率受服务端带宽与限速约束。
- **直连优先**（2026-10-21 起）：打洞时会同时互换双方的内网地址并行尝试——两台设备在同一局域网、或一方有公网 IP 可直达时，无需穿透 NAT 即可即刻建立直连；不满足时打洞行为不变，无需任何配置。

### 0.2 访问入口

| 端 | 地址 | 说明 |
|---|---|---|
| 客户端本地管理页 | `http://127.0.0.1:7100/?token=…` | 仅本机回环可达（Linux/远程机用 SSH 隧道 `-L 7100:127.0.0.1:7100`）；**2026-10-23 起须带 token**（见下） |
| 服务端管理后台 | `http://<服务端>:7500` | 默认仅绑定 127.0.0.1（不对公网暴露）——经 SSH 隧道 `-L 7500:127.0.0.1:7500`，或经一条映射到服务端机客户端的 `self:7500` 映射访问 |

两页面均为 Web 控制台（面向桌面浏览器）。**客户端管理页为双模式**（2026-10-20 起，§1.5）：打开默认进**简易版**（顶部 tab 三页：概览/端口映射/分组，日常高频操作都在这），右上角「高级版」进入全功能视图（左侧菜单带图标导航，共十页）；高级版顶栏亦有「简易版」一键回切。顶部横幅提示连接状态（「本地服务不可达」=客户端进程未运行）。

> **本地管理页 token 鉴权**（2026-10-23 起，M5-12；**2026-10-24 起默认关闭=页面直接可用，可在设置页开启加固**）：默认**关**——浏览器直接打开 `http://127.0.0.1:7100` 即用。需要加固的机器在**设置页「页面鉴权」开启**（§6.7，重启生效）——开启后本地 API/WS 须携带随客户端服务启动随机生成的 token：服务**自动打开**的 URL（首启向导/升级页）已附带 `?token=`；**手动输入地址**须从数据目录 `web-token` 文件读取当前值拼成 `http://127.0.0.1:7100/?token=<值>`（Windows：`%ProgramData%\P2PClient\web-token`，须管理员读取）。token 随服务**重启轮换**——遇 401 时重新读取该文件换新值（详见排障指南 §23）。威胁边界=文件 ACL：能读该文件的进程本就在信任边界内。

## 1. 首启向导（`/wizard`）

安装完成后浏览器打开 `http://127.0.0.1:7100`，未注册设备自动进入向导（已注册设备访问 /wizard 会直接跳回主界面）。三步：

### 第 1 步 · 服务端

1. 填**服务端地址**，格式 `host:port`（如 `203.0.113.10:7000`，端口默认 7000）；
2. 点 **「测试连接」**——显示「连接成功」后「下一步」才可用（未通过测试无法进入下一步；失败原因会显示在按钮旁）。

### 第 2 步 · 分组方式

三种方式选其一（决定这台设备与谁互通）：

| 方式 | 说明 | 附加输入 |
|---|---|---|
| **默认分组** | 加入服务端默认分组，与同分组设备互通 | — |
| **邀请码入组** | 输入 6 位分组邀请码（数字 2-9 + 小写字母去混淆字符集，不含 0/1/o/i/l），入组后与组内设备互通 | 邀请码（6 位） |
| **账号注册建组** | 新建账号并创建专属分组（「我的分组」）；其它设备用同一账号登录即可互见 | 用户名（≥3 字符）+ 密码（≥6 字符） |

再加一个**设备名**（默认「我的设备」，用于设备列表展示）→ 点 **「注册并完成」**。

### 第 3 步 · 完成

注册成功页展示本机三要素，**请妥善保管**：

- **远程码**（6 位，等宽字体展示，可复制）——其它设备建映射时用它定位本机；
- **虚拟 IP**（100.64.0.2）；
- **分组**（已加入的分组名）。

点 **「进入控制台」** 回到主界面（此时系统 phase 变为 running，向导不再出现）。

> 已有账号的场景：两台设备都选「账号注册建组」但用**同一用户名密码**？不行——账号注册是**新建**账号；第二台设备应在向导选「默认分组」或「邀请码入组」注册后，再到「账号登录」页用既有账号登录（§3），即实现同账号互见。

## 1.5 简易版（默认视图，`/simple`）

向导完成后打开管理页**默认进入简易版**——面向日常使用：顶部 tab 三页（**概览 / 端口映射 / 分组**），内容水平居中；顶栏右侧依次为在线状态、登录身份、「高级版」切换。未登录（哑节点）时三页仍可浏览，但写操作按钮置灰并有横幅提示（§3.2）。

简易版为**深色科技感主题**（深蓝黑底+青蓝霓虹点缀，数据大字带辉光，在线状态点呼吸发光）；此主题仅简易版使用——切到高级版即恢复浅色常规视图，两版观感独立互不影响。

### 1.5.1 概览

三张卡 + 一个主按钮：

- **本机**：在线状态 + 设备名 + **远程码（点击即复制）**——把远程码给对方，对方就能建映射连到你；
- **实时速率**：本机全部映射的上/下行总速率（无流量时显示空态）；
- **映射**：共 N 条 + 直连/中继/打洞中/停用分项计数；**有失败时显示红色「失败 N，点此处理」**，点击直达映射页；
- **新建映射**：主按钮，直达映射页并自动打开引导向导（§1.5.2）；
- **关于项目**：页底卡片——项目简介（基于开源项目 P2PSocket 的 AI 重构产品）、仓库地址（新窗打开）、**原项目地址**（新窗打开）、**QQ 群号（点击即复制，欢迎加入交流）**；更多信息与项目里程碑时间轴见「高级版 · 关于页」（§6.8）。

### 1.5.2 端口映射（卡片列表 + 引导式新建）

每条映射一张卡：名称/状态/启停开关（停用有二次确认）、**连接地址**（`虚拟IP:本地端口`，点击即复制——本机应用连它）、目标（设备名（远程码）· 协议:端口）、速率与路径行；**失败卡红底显示中文原因（如「打洞超时」）并带「重试」按钮**。卡片右侧「⋯」菜单：**高级编辑**（跳高级版映射页，可改全部字段）与**删除**（二次确认）。

**新建映射（四步引导）**：

1. **选设备**：下拉框输入设备名或远程码搜索（选项显示「设备名（远程码）」）；**离线设备不可选**（标注「离线」）；
2. **选服务**：协议 TCP/UDP + 目标端口；常用服务一键填入——**80 网页 / 22 SSH / 3389 远程桌面 / 53 DNS（自动选 UDP）**；需要访问目标设备内网其它主机时展开「高级」选 IP 地址（对端开放网段自动提示，段外会被拒）；
3. **本机端口与名称**：已按目标服务自动预填（本地端口=目标端口、名称=设备名-端口），可直接用；页面实时预览连接地址；
4. **确认**：核对摘要后点 **「完成并启用」**——一步创建并立即开始打洞（与高级版「创建默认停用」不同：简易版默认一步到位）。创建/启用失败会显示在当前页（如端口冲突），启用失败时映射已创建为停用态，可在列表中手动启用。

### 1.5.3 分组

行式列表：分组名 · 成员数 · 我的角色（所有者/成员）。所有者行有**「待审 N，去审批」**入口（跳高级版分组页的审批弹窗，§5.2）；「凭码入组」按钮打开弹窗输入 6 位邀请码（需审批的分组提交后显示等待提示）。建组、成员管理、邀请码等更多操作在高级版（§5.2）。

## 1.6 Android 客户端（M8，端口映射模式）

Android 手机上的客户端 App（`P2PSocket-Client-Android-v<版本>.apk`，自签名自分发）——把注册/打洞/映射/中继兜底/管理页全套能力带到手机，与桌面客户端同一账号体系互为对端、天然互通。

**安装**：sideload 安装 APK（需允许「未知来源/安装未知应用」权限；首次安装即自签信任，升级须用同一签名——卸载重装后数据目录清空=视为新设备重新注册，设备身份经 ANDROID_ID 指纹在卸载重装间保持稳定）。**要求 Android 8.0+**。APK 构建、装机与升级全流程见 [Android 客户端部署手册](../deploy/Android客户端部署手册.md)。

**使用形态=端口映射模式（无卡模式）**：App 不建虚拟网卡、零 VPN 权限——映射监听绑在 `127.0.0.1`（与桌面绑 100.64.0.2 不同）。**手机上任意 App 连 `127.0.0.1:本地端口` 即直达对端内网服务**：远程桌面（RD Client 填 `127.0.0.1:3389`）、浏览器、SSH 工具等同理。App 本体=全屏 WebView 管理页（简易版/高级版/向导与桌面完全同源，已做小屏适配），数据面由常驻前台服务承载（通知栏「P2P Socket 隧道运行中」）。

**后台保活**：前台服务=系统能给普通 App 的最强保活承诺，锁屏/切后台隧道持续；另支持**开机自启**（已启动过一次后生效，部分厂商 ROM 需手动授权自启）。厂商激进省电（Doze/电池优化白名单外）仍可能杀进程——建议把 App 加入**电池优化白名单**（设置 → 电池 → 不受限制/允许后台运行，各厂商入口不同）；被杀后重启 App 或开机自启会自动恢复映射，隧道断开期间的连接需重连。**不承诺全部 ROM 生效**——这是 Android 生态现实，非实现缺陷。

**蜂窝网络预期**：运营商 4G/5G 多为对称型 CGNAT，打洞成功率天然偏低——按既有逻辑自动回退内置中继（功能不断、速率受服务端带宽约束）；Wi-Fi 下与 PC 体验一致。此为网络现实非实现缺陷，无需报障。

**管理页地址**：App 内 WebView 自动加载（带 token），无需手动输入；同机浏览器也可开 `http://127.0.0.1:7100`（Android 上 localhost 全 App 互通）。

**注意事项**：① 映射本地端口并入手机回环冲突域——与手机上其它 localhost 监听（含本客户端管理页 7100）同域，端口被占会走 listen_failed 重试（§4），建映射时避开常用端口；② 明文 HTTP 仅对 127.0.0.1/localhost 放行（networkSecurityConfig），访问公网明文站不受影响；③ Web 宿主万一启动失败（端口被占等）App 仍保持隧道可用（降级不拖垮数据面，设计 13 §5.2）——此时 WebView 显示错误页，杀掉占用进程后重启 App 恢复。

## 2. 仪表盘（客户端高级版 `/dashboard`，原 `/`）

高级版首页（简易版概览的完整版），四块内容：

1. **设备信息卡**：远程码 / 虚拟 IP / 控制通道（连接状态）/ 登录态；
2. **速率图**：本机所有映射的上行/下行/中继速率实时曲线（纯 SVG，10s 刷新）；
3. **映射速览表**：名称 / 本地监听 / 目标远程码 / 路径（直连 / 中继）/ 实时速率；
4. **流量汇总卡（本次运行累计）**：按设备维聚合的上/下行/中继字节与总计——**本机视角、进程重启后清零**（服务端另有全生命周期累计）。右上「导出 CSV」= 两段式表格（映射明细+设备汇总）新窗口直下，Excel 可直接打开（UTF-8 BOM）。

### 重置远程码

信息卡上「重置远程码」按钮（哑节点亦可操作）：

- 确认弹窗会提示：**重置后旧远程码立即失效**——引用旧码的映射与打洞请求将被拒绝（错误码 4003，见 §8 速查），对端会收到失效提示并需改用新码；
- 确认后新码以弹窗一次性展示（不再显示第二次，请当场记录）；
- 典型用途：怀疑远程码泄露、或整理设备命名体系。

## 3. 登录与账号（客户端 `/login`）

### 3.1 登录（绑定账号）

未登录进入本页为**全屏居中**登录表单（2026-10-20 起，与服务端管理后台登录页形态一致）；登录后本页变为嵌入布局的账号管理卡。表单输入**用户名 + 密码** → 登录。登录后本机与「同账号设备」互相可见（可见性=同账号 ∪ 同分组）。顶栏显示 `用户名（已登录）`。

### 3.2 登出与哑节点

点「登出」会先弹出**二次确认**（2026-10-20 起，防误触），确认文案已说明后果：**登出后本机转为哑节点——仅响应既有隧道，不能主动发起映射**（不重启、不注销设备）。哑节点状态下主动操作类页面（映射启停、分组管理等）按钮置灰；设备/分组/映射三页顶部显示「哑节点」横幅。恢复：在「账号登录」页重新登录——登录会自动重置连接能力（无需重启客户端或等待重连，2026-10-11 起）。

**登录态保持（记住我）**：登录成功后凭据在本机加密保存（Windows DPAPI；Linux 由文件权限保护），**客户端/电脑重启后自动登录**——无需再次输入账号密码，web 打开即为已登录态，端口映射同步自动恢复。**网络断开重连后同样自动恢复**（2026-10-18 起）：断线期间登录绑定随服务器会话丢失，重连成功即自动重放登录（服务端亦自动继承登录态，双保险），登录态与可见性无感保持；断线窗口内判「失败」的映射也会自动补试一轮。**登出即忘记**：登出会清除记住的凭据，重启后回到未登录状态（下次须手动登录一次）。修改密码后同样须用新密码重新登录一次。

### 3.3 修改密码

已登录态点「修改密码」弹窗：当前密码 / 新密码（≥6 位）/ 确认新密码 → 成功后**自动登出**，请用新密码重新登录。改密只影响账号口令，设备注册与映射不受影响。

## 4. 端口映射（客户端高级版 `/mappings`）——核心操作

> 新手建议先用简易版引导式新建（§1.5.2，四步带提示）；本页为完整表单形态，适合批量管理与精细字段编辑。

### 4.1 概念

一条映射 = 「本机虚拟 IP 上的一个端口」→「目标设备上可达的一个地址」。本机应用连接 `100.64.0.2:<本地端口>`，流量经隧道直达目标设备上的 `<目标地址>:<目标端口>`。

### 4.2 新建映射

列表页「新建映射」打开抽屉表单：

| 字段 | 说明 |
|---|---|
| 名称 | 自定义，用于展示 |
| 协议 | **TCP** 或 **UDP**（UDP 适合 DNS/游戏等场景；单条映射单协议，需要两种就建两条） |
| 本地端口 | 本机监听端口（1~65535，绑虚拟 IP 100.64.0.2） |
| 目标远程码 | 目标设备下拉（可按设备名或远程码搜索，选项显示「设备名（远程码）」）；**离线设备也可选**（仅标「离线」提示）——支持先建好映射、等对端上线再启用；也可从设备页「带入远程码新建映射」自动填入（2026-10-21 起与简易版同款下拉） |
| 目标模式 | **self**=目标设备本机（即目标设备自身回环地址，最常用——例如访问目标机上跑的 Web 服务）；**IP**=目标设备所在内网的其它主机（如 `192.168.1.50`，须在对端「网段」白名单内，见 §5.3） |
| 目标地址 / 目标端口 | IP 模式必填目标地址（IPv4/IPv6 均可）；目标端口两种模式都填 |

创建成功提示「**已创建（默认停用，启用后开始打洞）**」——新建映射默认停用，手动「启用」才开始打洞/转发，避免误动作。

### 4.3 启停 / 重试 / 删除与状态语义

操作列按钮随状态变化（哑节点下全部置灰）：

| 按钮 | 语义 |
|---|---|
| 启用 / 停用 | 启用=开始打洞并转发；停用=拆监听停止转发（配置保留；停用侧有二次确认——立即中断该映射流量，2026-10-20 起） |
| 重试 | **仅 failed 态提供**——打洞失败后重新尝试 |
| 删除 | 二次确认后连配置一起删除 |

状态标签（列表「状态」列）：

| 状态 | 含义 |
|---|---|
| 打洞中（punching） | 正在尝试直连 |
| **直连（direct）** | 打洞成功，设备间直连（最优路径） |
| **中继（relay）** | 打洞不可穿透，经服务端中继转发（需对端开启中继回退，§5.1） |
| 失败（failed） | 打洞失败且无回退资格——点「重试」，或检查对端中继回退开关 |
| **失效（invalid）** | 授权变更被服务端下线（对端网段移除/远程码重置/设备或用户禁用/退出共同分组）——置灰不可用，编辑修正后重新启用 |
| 已禁用（disabled） | 本地停用态 |

编辑约束：**停用态才可改本地端口/协议**（与服务端配置规则同口径）；名称/目标任意状态可改。

### 4.4 白名单网段提示（IP 模式）

目标模式选 IP 时，表单下方实时列出**对端设备配置的开放网段**，并提示「段外地址将被拒绝」。填写的目标地址若不在对端网段内，创建时服务端会以 4002 拒绝（见 §8 速查）——请先联系对端在「网段」页添加（§5.3）。

### 4.5 访问映射

本机应用连接 **`100.64.0.2:<本地端口>`**（注意不是 127.0.0.1——虚拟 IP 上的监听与回环同端口服务是两个独立监听位，排障时勿混淆）。

## 5. 设备与分组

### 5.1 设备发现（客户端 `/devices`）

展示**与本机互相可见**的设备（同账号 ∪ 同分组）：设备名 / 远程码 / 虚拟 IP / 分组 / 开放网段 / 在线状态，顶部可按分组筛选。**分组列按查看视角显示**（2026-11-21 起）：本账号设备显示其全部分组；跨账号设备仅显示与本机**共同的分组**——其余分组名属对方隐私，不展示。两列重点操作：

- **中继回退开关**（每设备一行）：开启后，到该设备的打洞失败时自动经服务端中继兜底（映射转 relay 态）；关闭则打洞失败即 failed。**目标设备在云服务器/受限 NAT 后时建议保持开启**（打洞大概率不可穿透，中继是常态承载）。
- **操作 → 新建映射**：带入该设备远程码直接跳转映射新建表单（§4.2）。

页面顶部哑节点横幅同 §3.2。设备列表为事件驱动刷新（对端上下线自动更新，无需手动刷新）。

### 5.2 分组（客户端 `/groups`）

**分组表**：分组名 / 准入策略 / 成员数 / 我的角色 / 操作。列出本机已加入的分组 + 该账号创建的分组（登录后账号创建的分组都会显示，即使本机未加入——同账号多台设备共享管理入口）。

- 我的角色=**所有者**：可「审批」「邀请码」「成员管理」「编辑」「解散」；
- 我的角色=**成员**：仅「退组」。

**凭码入组**（页头按钮）：输入 6 位邀请码加入目标分组；若该分组策略为「需审批」，提交后显示「等待所有者」提示（非错误），获批后入组。

**新建分组**：分组名 + 准入策略（自由加入 free / 需审批 approval）。创建者即所有者。

**邀请码**（所有者）：打开弹窗即生成当前分组唯一邀请码（覆盖式——重新生成则旧码失效）；可撤销（撤销后空态）。邀请码用于「凭码入组」与向导「邀请码入组」。

**成员管理**（所有者）：列出组内可见设备（同组过滤、排除本机），可将成员移出（二次确认，其跨分组可见性即时回收）。

**审批**（所有者）：您创建的分组，「成员数」列显示如 `2（待审：3）`——括号内为该组待处理申请数（无待审时显示 `2（待审：0）`）；操作栏点「审批」打开弹窗，列出该组待审批申请（申请设备/申请时间），每页 10 条，勾选一条或多条后「同意」或「拒绝」（批量处理、逐条生效），翻页后勾选不保留；该组全部处理完弹窗自动关闭。批准后申请设备立即入组、双方设备列表即时刷新。非创建者的分组不显示待审数与「审批」按钮。

**退组 / 解散**：均二次确认；解散会回收组内全部成员的跨分组可见性，不可恢复。

### 5.3 网段（客户端 `/segments`）——开放网段白名单

定义「**允许别台设备经本机访问的内网地址范围**」（L3 授权）。表单支持 CIDR（如 `192.168.1.0/24`）或**单地址**（如 `10.0.0.5`，按 `10.0.0.5/32` 处理）；页面标注即时生效语义：

- 添加/移除**即时生效**：引用本网段的既有映射若段外将立即失效（对端收到 invalid 提示）；
- 全开放须**显式**填 `0.0.0.0/0`（留空=什么都不放行，fail closed）；
- `self` 目标不受网段限制（恒放行），网段只约束 IP 模式映射。

## 6. 网络诊断与运维（客户端）

### 6.1 NAT 判型（`/settings` → 网络诊断（NAT 判型））

点「开始探测」执行 RFC5780 子集判型（**受限型 NAT 须等超时判据，全程可数十秒，请耐心等待**）。结果六维：

| 维度 | 读法 |
|---|---|
| UDP 映射类型 | **端口无关映射**（好，映射端点稳定）／**地址端口相关映射**（symmetric，UDP 预测打洞基本无望） |
| UDP 入站过滤 | **端点无关过滤**（好，任意对端可回）／地址端口相关过滤 |
| 公网映射端点 | 探测学到的本机公网端点 |
| TCP 端口分配 | **同时打开**／**顺序分配**（TCP 打洞 N≥2 可用性依据）／随机 |
| TCP 端口依赖 | 地址无关／地址端口相关 |

判型对直连可能性的粗读：双方均「端口无关映射 + 端点无关过滤」→ UDP 直连概率高；任一方 symmetric → UDP 直连难，期待 TCP 打洞或中继。若提示「服务端未配置第二地址（stun_alt_addr）：UDP 映射/过滤两维不可判（单公网 IP 降级）」——属服务端配置限制，请联系管理员（或参照部署手册配置 `stun_alt_addr`）。

### 6.2 设备连通性（隧道 PING）

输入**目标设备远程码（6 位）** → 探测（须先启用一条到该设备的映射以建立隧道；无活隧道时明确报错并提示）。结果：发送/接收（丢包直观可见）、最小/平均/最大 RTT、承载路径（直连/中继）。用于快速验证「到某台设备的隧道通不通、走哪条路」。

### 6.3 服务端连通性

对设置里**全部候选服务端地址逐个** TCP 探测（30s 预算），结果表逐行显示可达性——服务端迁移/多线路场景下确认哪条线路可用。

### 6.4 打洞队列与隧道 REKEY

- **打洞队列**：当前队列深度 + 正在打洞的目标（空闲时显示「（空闲）」）——排查「点了启用怎么没动静」。
- **隧道与 REKEY**：活隧道列表（对端/本端角色/承载）；每行「触发 REKEY」按钮手动轮换会话密钥（正常由定时自动轮换，手动用于安全演练/验证隧道活性）。结果文案：成功（ok）／非发起方（not_initiator——本端为响应方，须在对端触发）／忙（busy——上一次还在进行）／失败（failed，附明细）。

### 6.5 日志（`/logs`）

客户端运行日志 newest-first 浏览：**级别过滤**（debug/info/warning/error/fatal 精确类别）+ 分页（每页 200 条）+ 「导出」（按当前级别过滤、时间正序、纯文本附件新窗口直下）。日常排障先看 warning/error。

### 6.6 升级页与版本不符引导（`/upgrade`）

- **自动进入**：客户端协议版本与服务端不兼容时，控制通道被拒，浏览器自动打开 `/upgrade?reason=version` 并顶部警示「协议版本不兼容」——按「下载地址」取新版本，覆盖安装后重连即可（升级不丢数据：配置/凭据/映射在数据目录，见部署手册）。
- **手动查看**：菜单「升级」直达。展示最新版本 / 协议兼容范围 / 下载地址（el-link）/ 更新说明；服务端未配置或不可达时显示「暂无法获取升级信息」。**产物哈希行**（管理员已录入时，M5-14 起）：按本机平台展示对应分发件的 SHA-256（Windows→windows-setup / Linux→linux-tar），等宽字体可复制——下载后请核验哈希一致（防下载链路被替换产物）。
- **哈希核验方法**（每个分发件随包附 `.sha256` 清单，或汇总 `SHA256SUMS`）：
  - Linux / Git Bash：与产物同目录执行 `sha256sum -c P2PSocket-client-linux-v1.0.0.tar.gz.sha256`，输出 `…: OK` 即通过；
  - Windows PowerShell：`Get-FileHash .\P2PSocket-Client-Setup-1.0.0-x64.exe -Algorithm SHA256`，比对输出哈希与升级页展示值（或 `.sha256` 清单中 `*` 前的 64 位十六进制串）一致即通过。

### 6.7 设置页其余项（`/settings`）

- **设备名**（注册后可修改）：未改名前显示主机名（注册时的默认名）；输入新名（1~64 字符）→ 点「改名」即时生效——同步更新服务端记录，同账号/同分组其他设备的设备列表自动刷新；本机重启后名字保持（改名已持久化，凭据恢复重注册亦沿用，不会退回主机名默认值）；
- **服务端地址候选**：多候选列表（可上移/下移调优先级）——主地址失联自动切换下一候选；
- **本地 Web 端口**：改后**重启客户端生效**（页面有提示当前仍由旧端口服务）；
- **页面鉴权**（2026-10-24 起）：本地管理页 token 鉴权开关（默认**关**=页面直接可用）——**开**=加固：页面/API 须携带随服务启动轮换的 token（公用/多账户机器建议；开启后手动访问须自数据目录 `web-token` 文件取值拼 URL，见 §0.2）。改后**重启客户端生效**；
- **高级参数（只读）**：打洞并发路数/隧道保活/重连退避等（当前版本只读展示）；
- **关于**：版本号 / 构建提交（git 短哈希）/ 协议版本——报障时请一并提供。

> 顶栏若出现持续告警条「**虚拟网段冲突**：本机网络与虚拟网段重叠，映射通信可能异常」——本机物理网络占用了 100.64.0.0/24 网段，须调整本机网络或联系管理员调整虚拟网段（服务端 `virtual_subnet` 键）。

### 6.8 关于页（`/about`）

高级版菜单末位「关于」，纯展示两卡：

- **关于项目**：项目简介（基于开源项目 P2PSocket 的 AI 重构产品）、**仓库地址**（新窗打开 GitHub）、**原项目地址**（新窗打开，AI 重构的基础项目）、**QQ 群号（点击即复制）**——与简易版概览页底「关于项目」卡同源；
- **项目里程碑**：时间轴六节点——M1 核心链路（收官）、M2 打洞完整与授权闭环（进行中）、M3 管理面与可观测（收尾中）、M4 交付打磨（收官）、维护期持续交付、M5 安全加固（已立项）；绿色节点=已收官、蓝色=进行中。

## 7. 服务端管理后台（server-app）

浏览器访问 `http://<服务端>:7500`（接入方式见 §0.2）。

### 7.1 登录（`/login`）

- 首次部署账号 **admin / admin**——登录即弹「正在使用默认口令（admin/admin），请立即修改管理员密码」强制改密（当前密码/新密码/确认新密码 → 「保存并继续」）。**务必修改**：默认口令是最大安全隐患。
- 忘记密码：服务器上执行 `p2p-server --reset-admin` 重置回 admin/admin（见服务端部署手册）。
- 会话 8 小时有效，过期自动回登录页；同 IP 连续失败有限速（渐进延迟）。

### 7.2 仪表盘（`/dashboard`）

六组指标卡 + 打洞成功率 24 小时曲线：**在线设备数**（连接级真相源）/ 分组数 / 映射状态分布（直连/中继/失败/失效/未知）/ **中继**（自启动累计转发字节与活跃会话）/ STUN 请求放行与丢弃 / 打洞成功率（punch_stats 24h）。右下角版本角标（版本号+构建提交——与服务端后台对版本时看这里）。

### 7.3 用户（`/users`）

用户列表（用户名/角色/状态/设备数/创建时间）+ 两项操作：

- **禁用 / 启用**：禁用=该用户名下**在线设备立即降级哑节点**（收到 user_disabled 提示，主动操作全禁），心跳保持；启用后设备**重连即自动恢复**——重连时服务端继承登录态（用户已启用即继承生效）+客户端凭据自动重放，无需手动重新登录（2026-10-18 起；此前须重连并重新登录）。
- **重置密码**：生成 10 位**临时密码一次性弹窗展示**（「我已保存」后不再显示）——用户拿到临时密码登录后自行改密。

页头**注册开关**（开/关）：关闭后新设备「账号注册建组」被拒绝（默认分组/邀请码入组不受影响）——公开服务端防滥用的第一道闸。

> 内置 admin 不可禁用/重置（页面按钮置灰）——管理员失联走服务器 `--reset-admin`。

### 7.4 设备（`/devices`）

全量设备表：设备名/远程码/虚拟 IP/归属用户/系统/分组/在线（连接级，与禁用态正交）/状态（正常/已禁用）/创建时间。操作：

- **禁用 / 启用**：禁用=设备**立即断线**（登录/注册/信令全拒；引用它的映射在对端失效提示）；同 MAC 重注册也被拒。启用后设备重连即恢复。
- **解绑**（二次确认）：删除设备全部记录（分组/映射/统计一并清理）；**同 MAC 重新注册=全新身份**（新 deviceId/新远程码）。用于设备报废/换装。
- **重置远程码**：等价客户端侧重置（§2），新码弹窗一次性展示——管理员代操作场景。

### 7.5 分组（`/groups`）

总览表（默认分组置顶）：分组/所有者/成员数/待审批数/准入策略/创建时间。两块操作：

- **默认分组准入策略**（页头单选：自由加入 free / 需审批 approval）：双写生效——既改存量默认分组，也是后续新建分组缺省口径。
- **待审批队列**：跨全分组的 pending 申请（默认分组+approval 策略或各 approval 分组），逐条批准/拒绝——批准即入组、双方设备列表即时刷新。

### 7.6 映射（`/mappings`）

**只读**视图（映射的启停/编辑在客户端做，服务端不代操作）：名称/归属设备/目标（远程码或 IP:端口）/本地端口/启用/状态/上下行与中继流量/统计更新时间。支持**按归属设备**与**按状态**双筛选，顶部有状态计数聚合。流量列=客户端 30s 周期上报的全生命周期累计（与客户端本地「本次运行累计」口径不同，两视角互补）。

### 7.7 中继（`/relay`）

- **中继服务开关**：关闭确认文案已说明语义——**新的中继分配将被拒绝（5002），存量会话不受影响继续转发**（排水式关闭，不断业务）；重新开启即恢复放行。
- **限速（B/s）**：0=不限。全局令牌桶——**即时生效**；限速时存量中继降速等待、不打断，**新的**中继分配请求才会被拒。
- **会话表**：当前活跃中继会话（会话 ID/A 端与 B 端（控制 IP·承载）/转发字节/最近活跃/创建时间），10s 自动刷新——排查「为什么走中继、中继转了多少」看这里。

### 7.8 系统（`/system`）

- **配置项表**：39 个服务端运行键（分组可见行级编辑，bool 即存、枚举下拉、数值/文本改后「保存」点亮）。标注「**重启生效**」的 8 键（public_addr/stun_auth/stun_alt_addr/stun_rate_per_ip/stun_rate_per_device/stun_circuit_pps/log_level/web_max_connections——服务构造期/日志装配期/Web 装配期一次性读取）改后须重启服务端进程；其余键运行期现读即时生效（`relay_rate_limit` 与中继页限速同源）。非法值（超范围/格式错）服务端整单拒绝并显示原因。
  - 常用键速查：`registration_open` 注册开关（与用户页同源）、`default_join_policy` 默认分组策略、`public_addr` **云服务器必配**（NAT 部署下中继端点通告，见部署手册）、`update_url` 升级下载地址（**仅接受 https://**，http 拒收，M5-14）、`update_artifact_sha256` 升级产物哈希（JSON 三键 windows-setup/linux-tar/server-tar，升级页按平台展示）。
  - **安全键组**（M5 起，语义详见 §7.9 与[安全设计](../技术设计文档/07-安全设计.md)）：**告警通道**七键（`alert_webhook_url` 接收端与阈值/静默窗/开关，改动 ≤30s 生效）+「测试推送」按钮；**自动封禁**四键（`autoban_*` 触发阈值/时长，M5-08）；**监听面上限**四键（`control_conn_max_per_ip`/`control_conn_max_total`/`relay_join_rate_per_ip`/`web_max_connections`，M5-10——前三即时生效、web 上限重启生效）。
- **审计日志**：安全相关操作流水（newest-first）：时间/事件/详情，支持按事件类型过滤（如 `group_join`）+ 分页。审计不含密码/密钥/邀请码明文。

### 7.9 安全中心（`/security`，M5-09）

一站式安全态势与处置页（管理菜单第 8 项「安全中心」，Lock 图标）。处置动作完成后页面自动回读最新态势。

- **态势四卡**：登录失败 / 注册拒绝 / 信令拒绝 / STUN 丢弃——前三卡「今日（UTC）」大数 +「近 7 天」副标（滚动 168 小时窗口）；STUN 卡为「自启动累计」+启动时刻（无时间窗事件源，口径如实标注）。
- **处置区**：
  - **注册准入开关**快切（与用户页/系统页同源，即时生效——公开服务端遭滥用时的第一道闸）；
  - **自动封禁规则**回显（四键现值：触发窗口/次数阈值/封禁时长——详见下方黑名单说明）；
  - **四面命中计数**：黑名单在控制面/STUN/中继/Web 四个监听面的拦截计数（只含已触碰面，缺省 0）。
- **IP 黑名单表**：来源（手动/自动 tag）/原因/性质（永久或到期时间）/行级**解封**按钮；「**加入黑名单**」对话框（IP + 原因选填——手动加入为永久封禁）。被列 IP 在四个监听面全部被拒（控制连接/STUN/中继/Web 含登录与自助解封端点——被封 IP 无法经 Web 自助解封，须管理员处理）；**自动封禁**：同一 IP 在 600s 窗口内触发拒绝达阈值次（默认 20，`autoban_*` 四键可调）即自动封禁默认 3600s，到期自动解除。
- **踢全部会话**（红字按钮，二次确认）：断开当前**全部设备控制会话**并审计留痕——设备凭据仍有效、会自动重连，适用于可疑连接风暴时快速清场；**长效封锁请用黑名单**，两者互补（§13.4 不设拒连窗）。
- **静态加密状态**（M5-13）：未启用时页顶黄色横幅（启用指引见服务端部署手册 §2.7）；已启用但存在解密失败凭据行时红色横幅（对应设备凭据失效——设备侧表现为登录失败，须解绑后重新注册）。

**告警通道（webhook，M5-07）**：系统页 `alert_*` 七键配置——接收端 URL（**通用 JSON** POST，不绑定任何厂商）、登录失败/注册/STUN 三类触发阈值、静默窗（重复告警间隔）、总开关；触发后 30s 周期聚合推送，发送失败重试 3 轮后丢弃（不入审计）。配置后用系统页「**测试推送**」按钮验证连通性（接收端不可达会返回错误提示；测试直发不占静默窗、不受开关影响）。
